# 金箍棒 — 客户投诉分析

配置：`config.yaml`（本目录）。所有阈值/开关都在里面，代码零硬编码。
数据区：config `路径.数据区`（建议配置为仓内 work/ 下对应目录，不进 git）。
设计文档：`docs/superpowers/specs/2026-07-06-金箍棒客户投诉分析-design.md`。

**脱敏铁律**：任何写进报告/清单/预警点的摘要与典型例，一律去除客户可识别信息
（姓名、卡号、手机号、意见单号、开户行支行名），只保留业务事实。

## 口径与文案铁律（2026-07-21 用户定，勿走回头路）

- **问题点分隔符用「-」不用「/」**：问题点＝二级菜单-三级菜单（三级空则只取二级）。
  菜单名本身常含「/」（如"短信未达/延迟问题"），用「/」当连接符读者分不清哪个是层级分隔。
  改动在 `normalize.py`；改后必须重跑 normalize 重建底库，并同步迁移历史 `摘要.json` 的键名。
- **超时口径只认「超时天数」**：超时办结率＝超时笔数÷当期总督办单量，超时笔数＝「超时天数」≥1天的笔数。
  不采信「是否超时办结」标志位（真实数据 2026 年 5-6 月 3034 行只有 2 行填"是"，标志位不可用；
  旧口径把 6 月全行超时率算成 2.8%，实为 11.6%）。与原始数据《说明》sheet 的处室口径一致。
- **两张表的定义写清楚**：督办＝客户诉求已受理、**尚未形成正式投诉**的事前预警工单（须限时办结）；
  投诉＝已形成的正式投诉。督办投诉比照红警的演化方向是**督办→投诉**（行内两张表之间），
  不是"客户转向监管渠道"，报告里凡提及"演化"必须写明这一点。
- **报告首章固定为「报告说明」**：由 `report_notes.build_intro()` 从参数快照与数据推导，
  含数据范围与部门清单、预警级别认定规则、模型清单、L1/L2/L3 分析层级四节。阈值改了它自动跟着改。
- **正文脚注**：在 `叙述.json` 文本里写 `〔fn:KEY〕`，KEY 取自 `report_notes.footnotes()`
  （督办/投诉/红警/橙警环比/橙警超时/黄警/超时口径/深挖/问题点）。docx 落页底真脚注，
  md 落 `[^n]` 尾注，html 落上标+文末注释。同一 KEY 只在首次出现处落注。
- **正式报告不许出现技术痕迹**：Python 字典 repr、未渲染的 `**加粗**` 星号一律不得进 docx；
  改渲染逻辑后用 `officecli view <docx> issues` 复查。

## 主流程（触发词：投诉分析 / 金箍棒）

### Step 1 归一化
1. 确认用户已把新数据放入 `<数据区>/原始/`（任意文件名；同文件加 sheet 或独立文件均可）
2. 运行：`python .claude/skills/anzhi-tousufenxi-jingubang/scripts/normalize.py <数据区>`
3. 把输出 JSON 复述给用户：新入库月份+条数、未识别 sheet（如有→问用户怎么处理）、
   未映射主办单位（如有→提议映射到哪个标准部门，用户确认后写入 `底库/部门映射.yaml` 再重跑本步）

### Step 2 定量分析
1. 确定分析月份（默认底库最新月，用户可指定）
2. 运行：`python .../scripts/run_analysis.py <数据区>/底库 <YYYY-MM> <本目录>/config.yaml <数据区>/报告/<YYYY-MM>`
3. 复述：预警数（红/橙/黄各几条）、深挖候选（问题点+条数+预估字数）

### Step 3 L2 分批深挖（按 config `深挖` 段执行）
对每个深挖候选（级别在 `深挖预警级别` 内，红警优先）：
1. 预算检查：累计预估字数超 `总预算字数` → 停下报数，问用户是否放开
2. 单任务预估超 `子代理隔离阈值字数` → 用 Task 工具派子代理执行 3-4 步，只收回小结
3. 取文本：`python .../scripts/extract_texts.py <数据区>/底库 <月份> "<问题点>" <数据区>/报告/<月份>/深挖临时 --batch-chars <单批上限字数>`
4. 逐批读 batch_NN.txt，每批产出小结（抱怨主题×条数×典型例·已脱敏）；下一批只带小结
5. 全部批次读完，汇总写入 `<报告目录>/摘要.json`，结构：
   `{"<问题点>": {"归因": "...", "子问题": [{"主题":"..","条数":N,"典型例":"脱敏描述"}], "处理对症": "...", "空处理结果占比": "N%"}}`
5.5 **兜底类目必查**：问题点含「其他相关投诉」「其他财富业务问题」「无法归入上述内容」的，
   不论是否命中预警都要单独深挖——菜单名不含业务信息，不读原文就不知道客户在投诉什么，
   且高敏感条目（暴力催收指控、监管投诉倾向、员工违规举报）常藏在这里，按菜单统计的常规报表看不见。
   条数多时按部门分文件、派子代理并行精读，产出：子问题分类表（主题×条数×占比×典型诉求）、
   建议新增的登记类目清单（最有价值的产出）、处理质量、高敏感条目。结果写成自定义章节。
6. m08 有命中的活动：抽读命中条目原文确认是否真与该活动相关，结论并入摘要.json 对应条目或
   在报告活动专章下补一句"经核实 N 笔确与活动相关/均为同词误命中"
7. 预算内挤不进的橙警：跳过并记录，报告里标"未深挖，可手动触发"

### Step 3.5 撰写叙述（正式报告书面分析）

读 `<报告目录>/指标.json`（全部8模型定量结果）+ `摘要.json`（已有归因），撰写 `<报告目录>/叙述.json`：

1. **关键发现速览**：3-5条，每条 `{"标签": "简短标签", "文本": "一句话，含关键数字"}`，覆盖本月最值得关注的信号（红橙预警优先、超时率异常、集中度异常等）
2. **结论摘要**：编号段落列表（`["1. ...", "2. ..."]`），每条呼应速览要点、展开数字支撑，书面语言（参照经营分析报告风格，不用技术黑话）
3. **章节**：对 投诉情况/督办情况/督办转投诉预警/在途活动关联/重复发现问题清单 五个章节各写：
   - `叙述`：一段书面分析文字，引用具体数字
   - `洞察`：可选，数据层面的建议性观察（无则填 null）
   - `风险提示`：可选，红橙预警对应的风险提示文案（无则填 null，通常只有"督办转投诉预警"章节会有）
   - 本月无实质内容时（如无在途活动、重复问题数据不足3个月），`叙述`写"本月无在途活动/变更"或"数据积累中"类说明，`洞察`/`风险提示`留 null，不编造
4. **策略建议**：编号建议列表，每条 `{"标题": "建议一：...", "内容": "一段分析+行动建议"}`，基于本月实际预警/异常生成，不是套话
4.5 **自定义章节**：`章节` 里除五个固定章节外可加任意专项章节，追加渲染在固定章节之后。
   自定义章节除 `叙述`/`洞察`/`风险提示` 外可带 `表格` 字段（markdown，支持 `###` 小节标题与多张表），
   优先于模型默认表格。兜底类目专项、单问题点专项说明都走这个口子。
5. **去AI味自查**：叙述.json 写完后，连同 Step 3 里摘要.json 的归因/处理对症文字一并过一遍（本步骤新产出的所有自然语言文本都要查）：
   - 破折号（—）全文超过3处 → 逐处审查，能改逗号/句号的改掉
   - 粗体只用于真正需要强调处，不对名词/术语机械加粗
   - "**标题：** 说明"式内联标题列表 → 改写成连贯段落
   - 标题/列表前的装饰性emoji全部删除（预警级别🔴🟠🟡等既有业务约定符号不算）
   - 删除填充短语、模糊归因（"专家认为""行业报告显示"之类）、硬凑的三段式排比（"其一...其二...其三..."类），改用自然行文
   - 不用"张力""硬约束"等惯用高频词，改用平实说法
   - 每段读一遍：有没有"之所以...根本原因在于..."这类套话开场？有则改写成直接陈述事实
   - 引号统一用中文双引号「" "」，不用英文直引号「' '」
   - 少用"根因"，直接说原因是什么（如"原因是XX""主要因为XX"）

**脱敏铁律同样适用**：叙述文本不得含客户可识别信息。

### Step 4 渲染产出
1. 运行：`python .../scripts/render_report.py <数据区>/报告/<YYYY-MM> <本目录>/config.yaml`
   （产出 md报告/督办预警清单/投诉预警点文件/正式版html/INDEX.md）
2. 运行：`python .../scripts/render_formal_docx.py <数据区>/报告/<YYYY-MM> <本目录>/config.yaml`
   （消费 Step 3.5 的 叙述.json，产出正式版docx：封面+目录+彩色callout+matplotlib图表；
   叙述.json 缺失时仍可生成，章节叙述留空不阻塞）
3. 逐个打开产出抽查：数字钩稽（预警总览条数=各模型预警之和；排名占比合计≤100%）、
   叙述与摘要均无 PII、html 浏览器可开、docx 用 Word/WPS 打开后右键目录选"更新域"确认页码正常显示

**渲染约定（2026-07-08 用户反馈固化，report_outline.py/chart_images.py 已实现，勿走回头路）**：
- 环比变动明细展示为表格（问题点/上月/本月/变幅/类型），不写成大段文字堆砌
- 条形图每根柱子标注具体数值，超时率类图表标注单位（如"超时办结率（%）"），不让读者猜坐标轴含义
- 某章节若确有红/橙预警命中，紧跟该章节自动附一行灰色小字注释，说明该预警的判定标准（阈值来自 config 参数快照，非编造）；无预警命中则不显示
- 报告正文统一称"重复问题"（清单/模型/图表标题），不用内部代号"惯犯"（config.yaml 分析模型键名与 REGISTRY 内部标识符仍叫"惯犯"，不受此约束）

### Step 5 收尾
1. 向用户汇报：预警总览 + 升格建议（m07 惯犯清单→提议写入事件库 03-客户服务.md，用户点头才写）
2. `knowledge/log.md` 记一条运行记录——**插在文件顶部**（前言 `---` 之后、当前最新条目之前），该文件按日期降序，勿追加到文件末尾
3. 预警点文件已更新 → 提示 git 提交（`knowledge/tools/投诉预警点/当前预警点.md`）
4. 海马体检查点：有跨会话事项（如映射待补、深挖未完）按海马体规则写入

## L3 专题深挖（触发词：深挖 XX）
1. 用 extract_texts 加 `--all-months` 取该问题点跨月全量，切批规则同 Step 3（含预算/子代理阈值）
2. 产出专题报告 `<数据区>/报告/专题/YYYYMMDD-<问题点>.md`：
   跨月趋势、子问题结构演变、处理质量评价、根因假设、建议动作（转处室/写案例/升格事件库）

## 配置页（触发词：投诉分析配置）
1. 读 config.yaml，输出编号表格：| # | 参数 | 当前值 | 默认值 | 说明 |（默认值以本文件 git 初版为准）
2. 用户说"N 改成 X"/"恢复默认"/"停用某模型" → Edit config.yaml → 复述生效值
3. 提醒：改动随脑仓 git 提交，有版本记录

## 新增分析模型规范（用户提需求时照此扩展）
1. 在 `scripts/models/` 新建 `mNN_<英文名>.py`，实现 `run(ctx, params) -> {"指标","预警","md"}`
   （接口详见 models/__init__.py 注释与任一现有模型；预警条目字段：级别/表/问题点/依据）
2. `models/__init__.py` REGISTRY 加一行：`"<中文名>": "mNN_<英文名>"`
3. config.yaml `分析模型` 段加：`<中文名>: {启用: true, <参数>: <默认值>}`
4. `scripts/tests/` 加对应测试（用 conftest 合成夹具，禁真实数据），跑通后提交

## 错误处理
- 映射新值/未识别文件：报出问用户，不静默猜
- 预算超限：先停报数
- 活动方案库缺失/无在途：专章输出"本月无在途活动/变更"
- docx 失败：降级不阻塞
- 底库某月缺失：对应指标标"无数据"，不报错中断
