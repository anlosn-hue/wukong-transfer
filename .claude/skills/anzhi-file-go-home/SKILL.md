# 筋斗云·文件统一处理

## 触发

触发词：「筋斗云」「归位」「整理文件」。

`_raw/` 下新增文件时，悟空在当次会话中主动提示：「_raw/ 有新文件，建议运行筋斗云处理。」

---

## Phase 0：扫描

扫描 `_raw/` 目录，列出全部文件（含格式）。

若 `_raw/` 为空 → 告知「_raw/ 目前没有待处理文件」，结束。

---

## Phase 1：逐文件判断类型

对每个文件按以下优先级逐步判断：

### Step 1：文件名关键词规则

**优先判为活动材料**（以下任一命中）：
- 含：活动方案、营销方案、活动通知、推广方案、活动策划
- 含机构名关键词：他行、他机构、XX银行、XX信用社（或任何非本机构的机构名）

**知识类文件判归属**：

| 文件名特征 | 目标目录 |
|-----------|---------|
| 含：评估表、审核表、预案、申请表 | `templates/` |
| 含：六维、分级、排查要点、方法论 | `knowledge/tools/assessment-manual/` 或 `risk-checklist/`（读内容决定） |
| 含：通知、发文、考评、制度 | `knowledge/tools/管理机制/` |
| `.md` 文件 frontmatter 含 `scene:` 字段 | `knowledge/cases/` |
| 含：经验、总结、模式、最佳实践、入门 | `internal-comms/` |
| 含：流程、SOP、操作指引 | `workflows/` 对应子目录 |
| 含专项任务名称 | `knowledge/projects/` 对应子目录 |

### Step 2：文件名无法判断时，读取内容

支持读取格式：.md / .docx / .xlsx / .pdf
图片文件（.jpg/.png 等）无法读取内容 → 直接标记「待人工」。

读取内容后重新按上表判断；内容含活动要素（活动名/时间窗/客群/奖励机制）→ 优先判为「活动材料」。

### Step 3：仍无法确定

标记「待人工」，不移动，列在确认表中提示人工处理。

---

## Phase 2：生成待确认分类表

分两部分展示（有哪部分就展示哪部分，两部分都有就都展示）：

### Part A — 知识类文件（归位）

```
| # | 文件名 | 建议目标路径 | 分类依据 | 判断方式 |
|---|--------|------------|---------|---------|
| 1 | XXX.md | knowledge/cases/ | 含 scene: 字段 | 规则 |
| 2 | YYY.pdf | knowledge/tools/管理机制/ | 含"考评"关键词 | 规则 |
| 3 | ZZZ.docx | templates/ | 内容为评估表格式 | 读内容 |
| 4 | ???.xlsx | 待人工 | 内容无法判断归属 | 待人工 |
```

### Part B — 活动材料（提炼入活动方案库）

对每个活动材料，展示提炼结果：

```
📋 从「XX活动方案.pdf」提取到：
来源：外部/他机构
机构：XX银行
活动名：暑期理财节
客群：存量理财客户
时间窗：2026-07-01 ~ 2026-07-31
关键词建议：暑期理财、积分抽奖    ← 悟空建议，可补充或修改
（渠道、玩法类型未识别，建议手动补充）

[确认入活动库] [修改后入库] [跳过]
```

未能识别到的字段一律留空，不瞎填。

---

## Phase 3：用户逐行确认

**Part A 确认方式：**
- 用户可逐行修改目标路径（「第3条改到 knowledge/tools/assessment-manual/」）
- 或驳回（「第2条跳过」）
- 未说明的条目默认按建议执行

**Part B 确认方式：**
- 逐条选择：确认入库 / 修改后入库（给出修正字段）/ 跳过
- 「修改后入库」时，用户直接给出修正字段，悟空更新草稿后入库

---

## Phase 4：执行与收尾

### 4A — 知识类文件搬移

按 Part A 确认结果执行：

1. 搬移文件到目标路径（`_raw/` 中对应文件删除）
2. 对所有搬移的 `.md` 文件执行 **Markdown 损坏扫描**：
   - 搜索 `\\\` → 疑似代码围栏被转义损坏
   - 搜索出现在行内非缩进位置的制表符 → 疑似反引号吞掉首字符导致路径损坏
   - 命中时列出文件名与行号，**不自动修复**，提示人工确认
3. 在 `knowledge/log.md` 记一条（**插在文件顶部**，前言 `---` 之后；该文件按日期降序，勿追加到文件末尾）：

   ```
   YYYY-MM-DD | ingest | 筋斗云 | 归位 N 个文件：[文件名列表]
   ```

4. 提示：「是否需要更新 `knowledge/INDEX.md`？」（不强制，用户决定）

### 4B — 活动材料入库

按 Part B 确认结果执行，对每条「确认入库 / 修改后入库」：

**生成卡片文件**，写入 `knowledge/活动方案库/YYYYMMDD-机构简称-活动名.md`：

```yaml
---
activity_id: YYYYMMDD-机构简称-活动名缩写
name: 活动名
source: external
category: 活动 / 系统维护  # 二选一，决定盯盘窗口分流与日历分类展示；无法判断时填「活动」
dept: 机构名
audience: 客群（未识别则留空）
type: 玩法类型（未识别则留空；注意与 category 不是一回事）
channel: []（未识别则留空）
start_date: YYYY-MM-DD（未识别则留空）
end_date: YYYY-MM-DD（未识别则留空）
goal: （未识别则留空）
risk_keywords: [关键词1, 关键词2]
risk_level:
assessment_path:
status: 进行中
sfe_checked_dates: []
---

## 玩法说明
（从材料提炼；无法提炼则留空）

## 预判风险点
（留空，供后续人工补充）
```

**更新 INDEX.md**，追加一行（**12 列，列序必须与 INDEX.md 表头完全一致**：活动ID/活动名/来源/类型/客群/时间窗/渠道/状态/风险等级/舆情关键词/下次盯盘节点/评估校正）：

```
| activity_id | 活动名 | external | 活动 或 系统维护 | 客群 | start_date~end_date | 渠道 | 进行中 | - | 关键词（逗号分隔）| 下次盯盘节点 | - |
```

- **「类型」列必填，取值只能是 `活动` 或 `系统维护`**（与卡片 `category` 字段保持一致，无法判断时填 `活动`）——这是盯盘窗口分流的依据：活动类走五节点（start−1/+0/+1/+3/+7），系统维护类走两节点（start+0 / end+2）。
- **「下次盯盘节点」列**：活动类填 start_date−1 天、系统维护类填 start_date 当天；若该节点已过则顺延到下一个未过的窗口；全部窗口已过填 `-`；**start_date 为空则标「待确认」**。
- **「风险等级」「评估校正」列**：外部参照卡未经本机构评估，均填 `-`。

更新 INDEX.md 顶部「更新时间」为今日。

---

## 业务规则

| 规则 | 说明 |
|------|------|
| `_raw/` 是统一入口 | 所有新材料扔 `_raw/`，筋斗云统一处理两种材料 |
| 先确认后执行 | 分类表须用户确认，不静默移动或入库 |
| 活动材料不归位知识目录 | 走 Part B 入活动库，不放 knowledge/ |
| 损坏只报不修 | 发现疑似损坏，列出提示，不自动修改 |
| 待人工不阻塞 | 无法判断的文件标「待人工」，其余照常处理 |
| 未识别字段留空 | 宁可留空待补充，不乱猜填入 |
