# 照妖镜 — 活动评审

> 适用阶段：活动设计初期（处室正式发起申请前）
> 评审原则：发现已有内容的风险，而不是检查材料是否齐全

宣布："使用照妖镜技能，对活动方案进行全面评审。"

**启动前加载（全量）：**
读取以下路径下的全部文件：
`./knowledge/tools/六维规则库/`

`./knowledge/tools/声誉风险事件库/`
`./knowledge/cases/`（先读 INDEX.md，再按规则加载文件）

## Phase 0：材料解析

识别收到哪些材料，缺失的记"未提供"，不报错。

**材料清点（硬性，不可跳过）：** 用户给出文件夹路径时，用 Glob 枚举全部文件，输出材料清单（文件名+类型），图片文件单独列出张数并回报，逐张尝试打开确认可读性。无法打开的图片如实标注在清单中，**不静默跳过**。图片的具体审察判断留待 Phase 1 宣传物料检查环节（见下）按七组要点统一执行，发现来源标注 `[图片:文件名]`。

内部整理（不输出给用户）：

已收到材料：[活动方案 ✓/✗] [宣传物料 ✓/✗] [触客话术 ✓/✗]
图片素材：[共N张，已审察X张，无法读取Y张 / 无]
活动名称：
活动类型：（促销/联名/线上/线下/数字化/其他；"线上"指渠道维度，"数字化"指活动形态，若重叠取更具体的用于后续匹配）
目标受众：
渠道：
奖励/激励机制摘要：
时间窗口：
待定字段：[列出未知的]

**材料解析完成后，立即调用顺风耳快扫：**

从以上提取字段派生关键词组：取活动名称核心词 + 奖励机制摘要中的产品/奖品名，去掉"活动""方案""评审"等通用词，以逗号分隔。

以如下格式调用 `anzhi-issue-shunfenger`：
args：`模式=快扫;关键词=[核心词1],[核心词2];行业=银行`

示例（理财日抽奖活动，奖品为微信立减金）：
args：`模式=快扫;关键词=理财日,微信立减金,积分;行业=银行`

将顺风耳输出的「⚡ 热榜速览」展示给用户，随后继续 Phase 1，不等待确认。
若顺风耳输出含 ⚠️ 升级标注，在 Phase 5 综合研判时将其纳入情节严重参考因素，可酌情将基础定级托底三级。

## Phase 1：活动专属规则检查

按收到的材料类型分别检查（未提供的跳过）：

**活动方案（如有）：**
- 奖励机制完整性：条件/兑付方式/有效期/限制条款是否齐备
- 规则歧义：是否存在有多种解读方式的表述
- 边界情况：极端情况下规则是否清晰（如超额兑付、提前截止）
- 羊毛党/黑产漏洞：规则是否存在可被批量薅取的漏洞（如不限次参与、虚拟号可重复领取、无身份验证机制）；规则漏洞被利用后正常客户是否会产生"不公平"投诉
- 渠道触达规则（从活动方案提取）：触达时段是否合规（短信/外呼不得早8点前/晚8点后）；单客频次是否有限制约束；未说明时标注"建议补充：投放时段约束、单客频次上限"

**宣传物料（如有）：**
- 广告法合规：
  - 绝对化词语：检查"100%""必得""免费""最优""第一""最高""绝对"等
  - 夸大表述："大幅提升""超高收益""无风险"等
  - 比较性表述：与同类产品比较时是否有数据支撑
  - 保证承诺：是否有收益保证类表述
- 消保知情权：活动核心规则（参与条件/限额/截止时间）是否在宣传材料中清晰披露
- 《金融产品网络营销管理办法》禁止用语（2026年9月30日起施行）：检查"低风险""低门槛""秒到账""高收益""低利率""无成本"等诱导性用语；保本承诺/预测未来业绩/模拟业绩展示；发现即标注**二级风险**，注明"建议在法规生效前完成整改"
- 理财收益表述：涉及理财产品时，检查是否使用"预期年化收益率"（监管已明确要求替换）；合规表述应为"业绩比较基准"
- 饥饿营销核实：使用"仅此一天""限量""秒杀"等表述时，检查是否与活动方案中的实际库存/时间一致；不一致即为广告法虚假宣传风险
- 版权合规：字体、图片、IP 形象是否有授权说明；地图（若使用）是否经品牌/办公室审核；此项为提醒性检查，标注"需确认授权"；**物料含图片时升级为看图核对**（按 `图片素材审察要点.md` 第 4 组）
- 图片物料逐张审察：Phase 0 材料清点发现的图片，按 `六维规则库/图片素材审察要点.md` 七组要点执行，发现按其第 8 节维度映射表"照妖镜归入"列对应归入本技能各 Phase 一并输出，来源标注 `[图片:文件名]`；品牌 VI 细审仍留 Phase 4 预留接口

**触客话术（如有）：**
- 广告法合规：同宣传物料检查标准
- 诱导性表述："今天不买就没了""限你一人专属""名额仅剩N个"等心理施压表述；杀熟嫌疑——同一活动中不同客群看到差异化权益且差异未在话术中说明，存在被截图对比引发"大数据杀熟"舆情风险
- 诱导裂变：是否要求客户转发朋友圈、邀请好友助力才能获取奖励；此类设计为监管重点关注对象
- 关键信息完整性：话术是否包含必要信息（费率/期限/风险提示等适用项）
- 客诉敏感点：容易被截图、断章取义的措辞

**跨材料一致性（钩稽比对）：**
逐字段在 方案 / 物料 / 话术 间交叉核对，任一项串不上即为材料硬伤。重点字段：
- **参与对象 / 客群范围**（方案"全行客户" vs 物料"全行零售客户" vs 话术"白名单客户"）
- 活动时间窗口、优惠力度 / 门槛、权益数量 / 库存、利率 / 费率 / 收益数字、活动名称、适用产品 / 渠道范围

冲突定级规则：
- 参与对象 / 核心承诺不一致（如客群范围冲突，或方案说限额100名而话术未披露）→ **二级风险**（消费者知情权 / 公平交易权）
- 关键表述冲突（如方案说"最高返现"，物料写"必得返现"）→ **二级风险**（广告法绝对化词语）
- 细节描述不一致但不影响核心权益 → **三级风险**

**处理原则：** 不默认任何一方为准，一律退回处室明确口径——物料口径比方案宽会导致不符合条件客户无法兑现（虚假宣传），比方案窄会导致应享客户被排除（公平交易权投诉），两个方向风险不同。
**仅提交一类材料时：** 跨材料比对无法执行，退一步与活动方案 / 评估表的自述口径自洽性核对。

## Phase 2：六维评估

基于已加载的六维规则库，按以下顺序逐维评估。

早期方案信息不足时，不跳过、不扣分，输出：
> 当前信息不足以评估，建议后续补充：[具体说明缺什么]

| 维度 | 评估操作 |
|------|---------|
| 政治敏感性 | 检查活动主题、命名、时间节点是否触碰政治敏感点；参考规则库对应文件 |
| 流程合规性 | 按规则库检查活动申报/发布流程合规要求；信息不足时提示需补充内容 |
| 材料规范性 | 按规则库检查材料规范要求；信息不足时提示需补充内容 |
| 事项合理性 | 检查活动设计合理性（受众匹配度、激励设计合理性、边界情况处理） |
| 评估准确性 | 对照六维规则库 INDEX，确认政治敏感性、流程合规性、材料规范性、事项合理性四维是否均已评估（本维度为兜底自检，不自我指涉）；列出未评估的维度并说明原因 |
| 预案完备性 | 基于 Phase 1–2 已发现的风险点，提示需准备哪些应对预案 |

**各维度赋级要求：** 每个维度发现实质性风险时，参照 Phase 5 定级表（一级：政治敏感/监管红线；二级：明确违规；三级：可修改风险；四级：完善建议），标注该风险点的初步等级。Phase 5 综合定级时直接取各阶段已标注等级中的最高值。

## Phase 3：三源情报

顺序执行，结果带入 Phase 5。

**情报源①：内部事件库 + 行业案例库**

读取 `./knowledge/tools/声誉风险事件库/` 全部文件，按活动类型 + 关键词匹配，查同类活动历史风险点和已知高危规则。

同时读取 `knowledge/cases/INDEX.md`，按 INDEX 加载指引执行：
- **内部案例**（scene 含 `内部·`）：与活动场景匹配，命中时加载
- **行业参照**（scene 含 `行业参照·`）：活动涉及监管合规、消保、营销宣传任一类型时，加载作为行业先例

同时读取 `./knowledge/tools/投诉预警点/当前预警点.md`（金箍棒月更），
按活动类型+关键词匹配近期客诉预警点，命中的摘录进情报源①结果，来源标注 `[投诉预警点:诉点名]`（诉点名取自预警点文件，写全称）。

输出规则：
- 内部事件库命中：摘录相关案例/风险点，来源标注 `[事件库:文件名#条目]`
- 行业案例命中：摘录相关事件，来源标注 `[行业案例:文件名#事件标题]`
- 均无命中时：记录"事件库及行业案例库无相关案例"，不影响定级
- 文件读取失败时：记录"事件库读取失败，本次未执行"，在备注标注评审范围受限

**情报源②③：舆情热点匹配**（由顺风耳执行）

调用 `anzhi-issue-shunfenger`，args 格式：
`模式=深查;关键词=[Phase 0 派生的关键词组];行业=银行`

（关键词组与 Phase 0 末尾快扫调用时使用的相同，无需重新派生）

将顺风耳输出的完整「舆情热点匹配」节（含热榜速览 + 近期同类风险案例）带入 Phase 5 输出。

调用失败/超时/不可用时：记录"网络情报源不可用，本次未执行"，在备注标注评审范围受限，不将失败当空结果处理。

## Phase 5：综合研判与输出

**去重/合并：** Phase 1、Phase 2、Phase 3（事件库）对同一风险点各自命中时，合并为一条，注明所有来源（如"[Phase 1 广告法 + Phase 2 事项合理性 + Phase 3 事件库]"），不在问题清单中重复列出。合并条目示例："**[1] [宣传物料] [Phase 1 广告法 + Phase 3 事件库：2024年某行同类处罚案]** 风险：使用'必得'等绝对化词语。建议：改为'最高可得'"

### 🚨 定级方法（硬性协议，不可跳过、不可用速记表代替）

**定级只有一种合法做法：逐维套《声誉风险分级模型》四维度，取孰高。**

第一步——打开 `knowledge/tools/六维规则库/05-评估准确性.md` §1"分级速查表"（源自《声誉风险分级模型》：事件性质 / 舆论背景 / 涉及范围 / 总体影响），**必读 §3"⛔ 定级铁律"**。
第二步——对本次活动**逐维**判定，每一维写出落在几级、命中该维哪条标准；无法判定的维标注"信息不足"，不猜。
第三步——**取四维最高者**为基础定级。
第四步——"定级依据"必须**点名是哪一维、命中哪条标准**（例："舆论背景维——理财导流恰逢工信部App跳转监管新规，与当下热点关联"），**禁止**只写"综合判断为X级"。

**⛔ 以下因素只写进问题清单/备注「提醒到位」，绝不抬高风险等级（详见 05 §2"偏高定级"表）：**
1. **送审材料缺失**（声誉风险事前评估表 / 消保记录 / 广告宣传规范审核表等）——活动评审是上线前的前置环节，后续还有声誉风险评估+审批流程补齐；只影响"总体结论"（范围受限、不出无保留通过），**不影响等级**。
2. **物料/页面占位符、原型稿未定稿**（占位文案、假数据、模板水印、联系方式占位、月份轴等样板值，含占位所致的跨材料不一致）——默认视为未定稿，只提示"正式发布前须填入/替换核对"，**不影响等级**。仅当占位内容本身反映活动设计缺陷才计内容风险。
3. **事件库/历史案例命中、系列活动重复未整改**——只佐证风险真实或反映处室执行力，**不单独提级**。

**❌ 禁止：** 用先例参照、速记表、"叠加了好几个问题"来代替逐维取孰高；把上述三类因素算作提级理由。

> 下表仅为**速记提要**，帮助快速定位量级，**不得据此直接下结论**——一切以逐维套四维模型为准：
>
> | 等级 | 速记提要 |
> |------|---------|
> | 一级（极高） | 存在政治敏感性问题，或违反监管红线 |
> | 二级（高） | 存在广告法/消保明确违规且达到分级模型量化门槛（涉弱势群体、性质较恶劣、已造成客户端实际误导等），或跨材料核心信息冲突已实际误导客户 |
> | 三级（中） | 违规程度未达二级量化门槛，但四维中某一维命中三级标准（如舆论背景与当下热点关联、涉及易贴标签群体等） |
> | 四级（低） | 四维均落四级：仅普通客户抱怨可安抚、无特殊舆情背景、普通利益相关者、影响范围小 |

**特殊情境处理（独立于基础定级，叠加执行）：**

| 情境 | 触发条件（从 Phase 0 提取） | 处理规则 |
|------|--------------------------|---------|
| 重大敏感时期 | 活动执行期与 3·15（前后各1周）或两会（3月上旬）重叠 | 基础定级强制托底三级；一/二级保持不变 |
| 高风险传播渠道 | 投放渠道包含小红书、抖音、微博等公域社交平台 | 专项注明"含公域渠道，舆情扩散速度快"，在备注标注，建议审批链知悉，不强制提级 |
| 年报/发债静默期 | 活动执行期可能与本行静默期重叠 | 专项注明"建议核实是否处于静默期，若是则暂缓大规模对外宣传"（悟空无法自行判断，提醒用户核实） |

**总体结论判定：**

| 结论 | 含义 | 判定锚点 |
|------|------|---------|
| 建议通过 | 无实质性风险，或有小问题已在意见中说明可自行处理 | — |
| 建议修改后推进 | 存在可修改的明确风险，处室调整后可发起申请 | — |
| 建议重新设计 | 存在方向性问题，修改局部解决不了 | 活动主题本身触碰政治敏感；整体模式涉嫌违规营销（强制消费/诱导欺骗） |

**材料不全时的约束：** 总体结论不得出无保留的"建议通过"，须在备注注明"基于现有材料，评审范围受限"。

**总体结论与等级的参考关系（独立，以下仅供参考）：**
- 一/二级 → 通常对应"建议修改后推进"或"建议重新设计"
- 三/四级 → 通常对应"建议通过"或"建议修改后推进"

**颜色规范：**
- 节头背景：P0 = `#C00000`；P1 = `#C55A11`；P2 = `#595959`；其他节头 = `#1E3A5F`
- 封面主色：`#1E3A5F`；副标题/下划线：`#2E75B6`
- 元数据表标签列背景：`#1E3A5F`（白字）
- 卡片浅底：P0 = `#FCE4D6`；P1 = `#FBE5D6`；P2 = `#F2F2F2`

**排版硬约束（2026-07-10 新增，防排版走样，逐条执行不可省）：**
- 每个表格（元数据表、结论框、卡片式双行表格）一律显式设置 `indent: { size: 0, type: WidthType.DXA }`——表格左缘必须与正文段落左缘对齐（2026-07-09 Web 版运行漏设此项，彩色模块与正文错位，本条即为此固化）
- 表格宽度一律用百分比 `width: { size: 100, type: WidthType.PERCENTAGE }`（徽章列等窄列按列宽分配），不用绝对 DXA 宽度
- 生成后自检（不可跳过）：读 docx 内的 `word/document.xml`，确认 `<w:tbl>` 的出现次数与 `<w:tblInd[^>]*w:w="0"` 的匹配次数**相等且均大于 0**；不满足即修 gen_report.js 重新生成，直到通过再交付
  - ⚠️ **必须用正则 `<w:tblInd[^>]*w:w="0"`，不可用固定串 `<w:tblInd w:w="0"`**（2026-08-05 订正）。docx 库 9.7.1 实际输出为 `<w:tblInd w:type="dxa" w:w="0"/>`，**`w:type` 属性在前**，按固定串检索恒为 0 命中，会把完全合格的文档判成不合格。属性顺序由库版本决定、不受本技能控制，故只认属性值不认顺序。
  - ⚠️ **解包方式**：Windows 上 `Expand-Archive` **拒收 `.docx` 扩展名**（只认 `.zip`），直接用会报错。改用 .NET `[System.IO.Compression.ZipFile]::OpenRead()` 读取 zip 内 `word/document.xml`，无需落盘解包。
  - ⚠️ **判定式写法**：`($tbl -gt 0) -and ($tbl -eq $ind)`。只写 `$tbl -eq $ind` 时，解包失败导致两边都为空会得出 `0 -eq 0` 的**假 PASS**（2026-08-05 实测踩中）。

## 沉淀尾步：知识轨沉淀（活动卡不在此建，移交火眼金睛）

> **两轨分离原则（2026-07-15 用户定）：**
> - **活动台账轨**（活动方案库卡片 + 盯盘）绑定"活动确定要上线"，由 **火眼金睛在上线前的声誉风险评估阶段建卡**。照妖镜是上线前诸多流程之外的**可选前置环节**，此时活动常未定稿、上线日常"待确认"、甚至可能不上线——**照妖镜不建活动卡、不写活动库、不调青云**。
> - **知识轨**（声誉风险事件库 / 案例库 / 排查要点）面向**跨活动复用**，价值在发现当下即产生、不绑上线——照妖镜发现库里没有的新隐患时**当场沉淀**，供后续所有评审（含次日就来的下一个活动）比对取材。

**Step A — 知识轨沉淀（发现新隐患才做，硬步骤，不可跳过判断）**

对照 Phase 3 三源情报比对结果，把本次评审的发现分两类处置：

- **命中已有条目**（事件库/case/投诉预警点已收录的隐患类型）→ **无需沉淀**，评审意见里标注命中来源即可。绝大多数评审属此类，**不得为凑数灌水**。
- **库里没有的新隐患类型 / 新排查要点 / 有典型价值的案例** → **当场沉淀**，不等火眼金睛、不管活动最终是否上线（哪怕活动被毙，该隐患对后续活动仍有效）：
  - 新隐患类型 / 排查要点 → 追加到 `knowledge/tools/声誉风险事件库/` 对应场景文件（如 `01-数字营销活动.md`）的"核心隐患要点/舆情场景"，写清 风险描述 + 监管依据 + 关联案例；隐患范式稳定的另可入 `六维规则库/` 对应维度文件
  - 有传播价值的典型案例 → 新建 `knowledge/cases/YYYYMMDD-关键词.md`，并在 `cases/INDEX.md` 追加一行
  - 每次实质沉淀后，在 `knowledge/log.md` 记一条（知识库操作留痕）——**插在文件顶部**（前言 `---` 之后），该文件按日期降序，勿追加到文件末尾
- **判据**：这条经验换个活动还用得上吗？用得上才进知识轨；只是本活动个例的风险点，写进评审结论「问题清单」即可，不进知识轨。

**Step B — 活动卡移交提示（照妖镜不建卡）**

在评审结论"备注"末尾注明一句：
> 本活动上线前须经声誉风险评估（火眼金睛），届时正式纳入活动方案库与盯盘；本次照妖镜仅出前置评审意见与前置风险等级，不建活动卡。

火眼金睛在声誉风险评估阶段建卡时，若该活动此前经照妖镜评审，**读取 `work/活动评审/` 对应结论**提炼预判风险点，等级/时间窗以声誉风险评估（定稿）为准。

Web 模式（悟空工作台任务）同理：**不写活动库、不生成建卡草稿**；Step A 若判定有新隐患，在 WUKONG_SUMMARY 的 pending 标注"新隐患待沉淀知识轨，终端确认"。

**为什么照妖镜不建卡（留档防回退）：**
- 盯盘窗口全绑 `start_date`（上线日），照妖镜阶段活动未定稿、上线日常"待确认"，盯盘空转；
- 进审批链的正式声誉风险等级出自火眼金睛（上线前必经），照妖镜等级仅前置参考；
- 活动可能大改/不上线，早建卡反复翻工；
- 谛听"评估校正"只认 `work/声誉风险评估/` 路径、忽略 `work/活动评审/` 路径——照妖镜建卡（`assessment_path`＝活动评审路径）会在评估校正时解析不出、进异常清单。故建卡统一收敛到火眼金睛。
