# 七十二变·活动方案共创

> ⚠️ **本技能仅负责内容共创，不出正式风险评审结论。** 文末历史坑提示仅供参考，正式风险定级须走**照妖镜（活动评审）**或**火眼金睛（声誉风险评估）**。

---

## Phase 0：识别模式与接收输入

判断使用场景：
- 用户提供了方案草稿（含活动规则/玩法描述）→ **改进模式**，进入 Phase 0B
- 用户只有想法/关键词/描述 → **生成模式**，进入 Phase 0A

### Phase 0A：生成模式输入

接受三种形式（自动识别字段，无需用户指定格式）：

| 形式 | 示例 |
|------|------|
| 关键词 | "中老年客群理财活动" |
| 结构化四件套 | 客群 + 主题 + 渠道 + 时间窗 |
| 自由文本 | "国庆期间面向中老年客群做一个理财体验活动，现场办卡送礼品" |

从输入中抽取：客群、主题/玩法类型、渠道、时间窗、激励机制。**未提供的字段不追问**，留待 Phase 2 用检索结果做假设填补。

### Phase 0B：改进模式输入

若用户未提供以下格式，直接从其描述/草稿文本中提取：

```
客群：________
主题/玩法类型：________
渠道：________
时间窗：________
激励机制：________

方案说明（自由文本）：
________________________
```

### 备料开关（正交判断）

在识别 0A/0B 模式的同时，判断是否需要生成配套文件（与输入模式正交）：

- 消息含「备料」「生成评估表」「生成预案」→ 备料开关开启
- Phase 0 开始时用户选择「方案+配套材料」→ 备料开关开启
- 备料开关开启 + 当前会话已有现成方案 → **直接进 Phase 5**，跳过 Phase 1-4
- 备料开关开启 + 无现成方案 + 活动类 → 走完 Phase 1-4 后，Phase 4 末尾自动进 Phase 5
- 备料开关开启 + 无现成方案 + 系统类 → **跳过 Phase 1-4**，直接进 Phase 5（活动方案库对系统无关）

## Phase 1：检索活动方案库

**读取文件：** 先读 `knowledge/活动方案库/INDEX.md` 获取候选列表，再读相关卡片 `.md` 文件获取详情。

**匹配逻辑（按优先级）：**
- 主维度：客群 + 玩法类型/主题
- 辅维度：活动目标 + 渠道 + 时间节点（节气/节日/季节）
- 步骤：按 INDEX 字段粗筛候选 → 读候选卡片正文 → 排序选最相关 1-3 条 → 提炼「可复用玩法」和「真实教训」

**降级机制（库内无同类活动，或 INDEX.md 不存在/为空）：**

改用通用经验库：
- `knowledge/tools/声誉风险事件库/01-数字营销活动.md`
- `knowledge/tools/六维规则库/` 相关维度文件
- `internal-comms/` 下经验文档
- `knowledge/cases/` 相关案例

在方案末尾声明：`⚠️ 活动方案库暂无同类历史案例，本方案基于通用风险经验生成，建议积累案例后再参考检索结果。`

## Phase 2（生成模式）：假设填补

Phase 0A 未识别的字段，参考 Phase 1 检索到的相似案例做合理假设，在方案对应位置标注**【假设，请按实际调整】**。

---

## Phase 2（改进模式）：比对改进点

对照检索结果与草稿，识别两类改进点：
1. 草稿可借鉴的更优玩法（来自检索卡片「可复用玩法」）
2. 草稿未覆盖、历史踩过的坑（来自检索卡片「真实教训」）

## Phase 3：输出方案

### 生成模式输出格式

```
# [活动名/主题] 方案初稿

## 背景与目标
[客群定位] + [活动目标]

## 玩法设计
[参考历史同类活动的可复用玩法，结合本次主题定制]
[标注来源：参考 YYYYMMDD-XXX 活动的 XX 玩法]

## 规则细则
- 参与条件：
- 奖励规则：
- 时间节点：
- 参与次数限制：
- 奖品核销方式：

## 话术建议
[推送文案关键要素 / 活动说明关键话术]

---
参考历史活动：
· [活动名]（YYYYMMDD，发起处室）[核心参考要素]
```

【假设】字段在对应行内用**【假设，请按实际调整】**标注。

### 改进模式输出格式

在原草稿基础上延展，**新增/调整处行内标注〔新增〕〔调整〕**（不另开清单罗列）。例：

```
## 规则细则
- 参与条件：持有本行借记卡（〔调整〕原草稿未明确是否含信用卡，建议仅限借记卡避免歧义）
- 奖励规则：〔新增〕建议增加"奖品数量有限，送完即止，请以实际到账为准"披露，避免告罄投诉
```

## Phase 4：历史坑提示

无论生成还是改进模式，方案末尾固定追加：

```
---
## ⚠️ 历史同类活动踩过的坑（参考，非正式风险评审）

· [坑描述1]（来源：YYYYMMDD-XX活动）
· [坑描述2]（来源：YYYYMMDD-XX活动）

💡 **下一步建议：** 方案成型后，可：
- 走**照妖镜**做正式活动评审，出具风险等级结论后再提交审批
- 说**「备料」**，生成配套的声誉风险评估表和应急/回撤预案初稿（备料不出风险等级，等级留占位符待正式评估后填入）
```

若走降级机制（通用经验库），将坑改为通用高频风险点，来源标注为「通用风险经验库」。

## Phase 5：补充信息收集（备料模式）

一次性列出，处室填完后进 Phase 6（活动类填①②③④⑥，系统类填①②⑤⑥）：

```
请提供以下信息以生成配套文件：

① 部门/机构名称：
② 类型：活动类 / 系统类
③ 渠道：（活动类）如 手机银行APP / 短信 / 企微 / push / 5G消息
④ 激励机制：（活动类）如 微信立减金 / 积点 / 抽奖 / 现金
⑤ 联系人：
   业务联系人姓名 + OA号：
   技术联系人姓名 + OA号：（系统类填写）
⑥ 文件输出路径：（默认 work/声誉风险评估/YYYYMMDD-活动名或系统名/评估内容/，可修改）
```

字段缺失处理（不阻塞流程）：
- 联系人未填 → 该位置写【待填写】
- 渠道/激励机制未填 → 对应场景行写占位符【请确认后填入】
- 类型未填 → 从输入关键词推断并请确认（含「活动」→ 活动类；含「系统」→ 系统类）
- 输出路径目录不存在 → Phase 7 自动创建

若从独立触发词进入且当前会话无活动/系统内容，额外询问：
「请提供活动方案内容，或告知活动名称（将从活动方案库检索）。」

## Phase 6：AI 深度预填，逐节确认

根据 Phase 5 信息和当前会话方案内容，生成以下所有字段并**逐节展示给处室确认**。
媒体备答口径统一生成一份（见下），评估表和预案均引用同一份，不重复生成。

### 6A：评估表预填（四节）

**一、评估事项（B列）：**
活动类：2-4句，含活动目标、时间窗、活动内容要素、可能声誉风险点。
系统类：2-4句，含系统变更内容、维护时间窗、受影响业务功能列表、可能声誉风险点。

**二、声誉风险评估：**

可行性分析（C列，对应 D 列「阐述可行性」的行）：
- 活动类：说明符合监管导向/民心所向，活动设计合理，时机成熟。
- 系统类：说明是主动落实监管要求/合规举措，已经过论证。

民众认可度分析（C列，对应 D 列「阐述群众认可度」的行）：
- 活动类：客群受益情况、规则透明性、可能的疑虑及已有的应对设计。
- 系统类：暂停时段是否低峰期、是否提前公告告知客户。

舆论关注度分析（C列，对应 D 列「阐述舆论关注度」的行）：
- 活动类：预判媒体关注可能性、历史同类活动舆情情况（参考 risk_keywords）。
- 系统类：是否主动合规举措（不易引发负面）、已制定备答/预案的说明。

风险发生概率（C列，「评估此项业务」所在行）：根据以上分析给出「低 / 中 / 高」。

**风险等级（C列，「根据本行声誉风险等级分类」所在行）：**
固定填写「【待照妖镜/火眼金睛正式评估后填入】」，不预判等级值。

评估结果运用（C列，「评估结果运用」所在行）：
- 活动类：方案报备客服、正面引导、妥善处理客户投诉。
- 系统类：提前公告渠道（官网/APP/网银）、客服报备、备答口径、预案说明。

**三、产品宣传环节及处置预案（B列，「三、产品宣传」所在行）：**
活动类：2-4句，含系统测试、活动细则报备客服、应急预案说明。
系统类：2-4句，含公告发布渠道、客服报备、回撤条件说明。

**四、媒体备答口径（B列，「四、媒体备答口径」所在行）：**

活动类 → 生成三问三答（Q&A 格式文本，写入 B 列同一单元格）：

```
问：活动推送是否有效保护客户的隐私权？
答：我们严格遵守个人信息保护法相关规定，推送服务仅基于客户授权的使用数据，绝不会泄露客户的个人信息。
问：截至目前，客户投诉问题是否已解决？
答：对于活动开展过程中部分客户反映的问题，我行正积极采取措施，尽快解决客户问题。由此带来的不便，我行深表歉意！
问：贵行是否对此次活动造成的客户损失进行补偿？
答：我行一贯将客户利益放在首位，将切实维护客户的合法权益，妥善处置相关问题。对于本次活动给客户造成的困扰，我行深表歉意，并同客户做好沟通解释，也将以此为契机，进一步优化活动开展和服务流程，切实维护好客户的合法权益。
```

系统类 → 生成概括段落（不展开 Q&A）：
「[系统名称]暂停服务，已提前通过官网/手机银行APP/个人网银发布公告，对客服报备备答口径，制定应急预案。完整备答口径详见回撤预案附件。」

### 6B：应急预案预填（活动类）

**客服备答口径场景行（按 Phase 5 的渠道和激励机制动态生成）：**

基础场景（含 push 或短信时必包含）：
| 情景状态 | 场景说明 | 回 答 | 注意事项 | 备注 |
|---------|---------|-------|---------|------|
| 当客户反馈为什么会收到push/短信推送时 | 收到客户反馈或投诉 | 因客户是我行优质客户，故通过push/短信推送相关活动信息，旨在让客户及时获取我行相关信息内容，并提供更优质的服务体验。 | | |
| 当客户表示不想收到相关推送时 | 收到客户反馈或投诉 | App消息推送建议通过兴业银行App-我的-消息-热门活动-取消订阅自行关闭。短信可建议客户通过短信回复"R"拒收。 | | |
| 当客户表示不想收到相关广告策略展示时 | 收到客户反馈或投诉 | 将为客户屏蔽该广告策略。 | | |

激励机制追加（含微信立减金时追加）：
| 当客户表示抽到的微信立减金无法使用时 | 收到客户反馈或投诉 | 获得微信立减金的客户，使用微信支付时绑定选择兴业银行借记卡，且订单实际支付金额大于立减金面额时方可抵扣使用，最终优惠金额以支付界面显示为准。可前往我行手机银行App"我的频道-我的业务-我的奖品"查看其使用规则。 | | |

**媒体备答口径：** 复用 6A「四、媒体备答口径」活动类三问三答，格式转为表格（媒体问题/回答/适用场景/备注四列）。

**投诉舆情处理：** 标准化文字，嵌入活动名称。
**方案优化：** 「根据投诉、舆情相关内容，优化策略投放逻辑及相关物料。」
**联系人：** Phase 5 收集的联系人信息，附「请勿提供给客户」。

### 6C：回撤预案预填（系统类）

**客服备答口径（3个标准场景）：**
| 情景状态 | 场景说明 | 回 答 | 注意事项 | 备注 |
|---------|---------|-------|---------|------|
| 维护期间暂停服务 | 维护时间窗内 | 因系统升级维护，相关功能暂停服务，给您带来不便，深表歉意！预计于XX时恢复，请耐心等待。 | 只说明客户关注的业务，无需将具体系统告知客户 | |
| 维护时间超预期 | 维护时间超过预期结束前 | 我行正在开展系统维护工作，目前暂停服务，给您带来不便，深表歉意！正采取措施尽速解决，感谢理解。 | 只说明客户关注的业务，无需将具体系统告知客户 | |
| 客户关于资金安全的疑问 | 适用于所有情景 | 我行一贯采取严格的措施，确保客户资金安全，本次系统维护不会给您的资金安全带来影响，请您放心！ | | |

**媒体备答口径（4个标准Q&A，嵌入系统名称和维护时间）：**
| 媒体问题 | 回答 | 适用场景 | 备注 |
|---------|------|---------|------|
| 为何[受影响功能]无法正常使用？ | 为提供更优质、高效的服务，我行定于[维护时间]开展系统升级维护工作... | 适用于维护超预期 | 媒体电话询问一律不接受，转相应办公室 |
| 本次系统维护是否提前告知客户？ | 本次系统维护前，我行已在手机银行App、兴业银行官网和个人网银上发布暂停服务公告... | 适用于客户知情权提问 | |
| 截至目前，系统故障是否已修复？ | 正积极采取措施，尽快恢复正常服务。由此带来不便，我行深表歉意！ | 适用于维护超预期 | |
| 是否对此次系统维护造成的客户损失进行补偿？ | 我行一贯将客户利益放在首位，将切实维护客户的合法权益... | 适用于维护超预期 | |

**投诉舆情处理：** 标准化文字，含系统名称和回撤逻辑（协调供应商停止切换或立即回切）。
**方案优化：** 「若发生严重客户投诉及舆情问题时，结合相关情况，协调合作供应商停止切换或立即进行回切。」
**联系人：** 业务联系人 + 技术联系人（两行，各附OA号和「请勿提供给客户」标注）。

### 确认流程

内容生成后，分两轮确认：
1. 展示评估表四节预填内容 → 询问「评估表内容是否确认？如需修改请指出。」
2. 展示预案核心内容（投诉处理段落 + 客服场景行数 + 媒体口径行数）→ 询问「预案内容是否确认？」

处室确认（或修改后再确认）后，进 Phase 7。

## Phase 7：生成文件与验证

**Step 7.1：准备数据 JSON**

将 Phase 6 确认的全部内容组装为 JSON，用 Write 工具写入临时文件：

- `[scratch_dir]/eval_data.json` ← 评估表数据（12个字段）
- `[scratch_dir]/plan_data.json` ← 预案数据（customer_qa / media_qa 等）

scratch_dir 使用当前会话的 scratchpad 目录（见会话环境变量 `C:\Users\Lenovo\AppData\Local\Temp\claude\` 下对应会话目录）。

**Step 7.2：创建输出目录**

确认 Phase 5 指定的输出路径存在，若不存在用 PowerShell `New-Item -ItemType Directory -Force` 创建。

**Step 7.3：运行评估表生成脚本**

```powershell
python "./.claude/skills/anzhi-qishierbian/scripts/gen_eval_table.py" `
  --template "./templates/声誉风险事前评估表.xlsx" `
  --output "[输出路径\附件X：声誉风险事前评估表.xlsx]" `
  --data "[scratch_dir\eval_data.json]"
```

**Step 7.4：运行预案生成脚本**

活动类：
```powershell
python "./.claude/skills/anzhi-qishierbian/scripts/gen_plan_doc.py" `
  --type activity `
  --output "[输出路径\附件X：应急预案.docx]" `
  --data "[scratch_dir\plan_data.json]"
```

系统类：
```powershell
python "./.claude/skills/anzhi-qishierbian/scripts/gen_plan_doc.py" `
  --type system `
  --output "[输出路径\附件X：回撤预案-[系统名称].docx]" `
  --data "[scratch_dir\plan_data.json]"
```

**Step 7.5：验证输出文件**

用 PowerShell 确认两个文件存在且大小合理（xlsx > 8KB，docx > 8KB）：

```powershell
Get-Item "[xlsx输出路径]", "[docx输出路径]" | Select-Object Name, Length
```

如有生成失败（脚本报错或文件不存在），将错误信息告知处室，不要静默继续。

**Step 7.6：展示完成提示**

