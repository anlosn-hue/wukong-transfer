# 谛听 · 事后反馈采集闭环

> 设计依据：`docs/superpowers/specs/2026-07-04-谛听事后反馈采集闭环-design.md`（v4）
> 脚本：`scripts/diting_excel.py`（generate/parse 管事后采集；generate-correction/parse-correction 管评估校正）
> 原则：悟空备草稿、用户拍板，不静默写库。

## 一、评估校正

### Step 1 圈批次

触发词「评估校正」手动触发（不自动、不绑会话启动）。全库扫描 `source: internal` 且 `review_feedback_status` 为空的卡片，按 `assessment_path` 能否解析出声誉风险评估路径分两类：

- **能解析出** → 进入 Step 2
- **解析不出** → 汇总成异常清单报用户："以下N个活动缺少声誉风险评估路径记录：[活动名列表]，请确认——是否遗漏记录（需补全 assessment_path）/ 是否人工线下评估无存档报告（标记免校正）/ 确实未走此环节"。用户逐条决定：补路径→下次自动转入正常入批；无存档报告→标 `review_feedback_status: 免校正-人工线下评估无存档报告`；应走未走→用户另行处理，不阻塞本次

**强制重入批**：若声誉风险评估报告有后续修订，用户可点名已 `已校正` 的活动重新纳入下一批，重置该活动 `review_feedback_status` 为空，批次JSON该行 `round` 递增。

### Step 2 提炼建议

逐活动定位并读取声誉风险评估报告全文（已有 .md 版直接读；docx 用 document-skills:docx 读）：

- **路径解析**：`assessment_path` 用" 及 "（**前后各一个空格**，不是裸字符"及"）分隔多条路径时，只取 `work/声誉风险评估/` 开头的那条/那几条，活动评审路径 `work/活动评审/...` 一律忽略。解析顺序：**①先按" 及 "分隔，②再逐条判断前缀**，无分隔符时才把整串当单一路径判前缀。顺序不能反——`work/声誉风险评估/A/ 及 work/活动评审/A/` 这类多路径串**本身也以目标前缀开头**，若先判前缀会把整串（含分隔符和活动评审路径）当成一条路径原样返回，后续必然读不到报告（2026-07-21 交接包 workflow.py 就是按反的顺序实现的，真实活动卡里就有这种写法）。同一活动有多条声誉风险评估路径时合并去重
- **兜底**：目录不存在、或目录内找不到评估意见文件时，到父目录按活动名模糊搜索（注意全角/半角引号差异）；仍找不到 → 报用户人工指路，不静默留空
- **多活动共用一份评估报告**（如按揭有礼与端午理财推送共用同一评估申请父目录 `work/声誉风险评估/20260610-按揭有礼活动及端午假期前理财产品营销策略/`，各自子目录）：按活动切分建议归属，归属不明的条目标注并问用户
- **提炼口径**：只取报告中"修改要求"性质的条目（六维评审意见里明确标"修改要求""必须补充""退回补充"等）；纯背景分析/风险描述/舆情热点参考不进列表
- **建议为空**：若提炼出的建议列表为空，生成批次时直接标该活动 `review_feedback_status: 已校正-YYYY-MM-DD`，跳过，不占表格行

### Step 3 生成

1. 组装批次JSON（schema 见 plan `docs/superpowers/plans/2026-07-04-谛听.md`）：批次号按 `work/评估校正采集/` 下当月现状取下一号（`YYYY-MM-批次N`）；`rows` 数组扁平罗列全部活动的全部建议，每条含 `activity_id`/`name`/`suggestion`/`round`；顶层另组装 `levels` 映射（`{activity_id: 卡片 frontmatter 的 risk_level}`，缺省可空），供校正表「风险等级校正」行预填原评估等级。生成脚本会给每条建议回写 `tag` 行标识（建议N）进批次清单.json——解析按活动ID+行标识定位，批次清单是定位事实源，生成后不要手改 rows 顺序
2. 批次JSON 存到 `work/评估校正采集/YYYY-MM-批次N/批次清单.json`
3. 运行：`python scripts/diting_excel.py generate-correction <批次目录>/批次清单.json <批次目录>`
4. 每张涉及的卡片标 `review_feedback_status: 校正表已发-YYYY-MM-DD`
5. 提示用户转发舆情管理员团队内部填写（不发业务处室，不用脱敏）

### Step 4 解析回填（用户说「解析」时）

1. 定位批次：用户给已填文件路径（所在目录即批次）；未给路径 → 列出在途批次让用户选
2. 运行：`python scripts/diting_excel.py parse-correction <已填xlsx> <批次目录>/批次清单.json <批次目录>/解析结果.json`
3. 检查 warnings（行被误删/脏值），有问题先报用户
4. 按 `activity_id` 分组，转译写入各卡片新独立节「评估建议采纳情况」；解析结果中的 `levels` 一并转译——每活动记一行「风险等级：原评估X级，最终执行Y级（原因）」；选"维持原级"记"维持原评估等级"；**留空的不静默按维持处理**，草稿中单独标注"（管理员未选，按维持处理，请确认）"交用户核；若最终执行等级≠卡片 `risk_level`，草稿中额外列出「拟同步更新卡片 risk_level 与 INDEX 等级列」待用户确认
5. 草稿呈用户确认后：每张卡 `review_feedback_status: 已校正-YYYY-MM-DD` + 更新 `knowledge/活动方案库/INDEX.md`「评估校正」列；**批次内全部活动均已出队**（已校正/免校正）时才在批次目录创建 `已写库-YYYY-MM-DD.txt` 标记文件（内容一行：写库日期+涉及卡片数），供网页直填面板区分批次状态；**部分写库**（尚有活动未填/未处理）改落 `部分写库-YYYY-MM-DD.txt`（内容注明已写库与待补填的活动清单），不落"已写库"标记——直填面板据此保持"已直填待写库"状态，用户补填后再次解析回填，已出队的卡不重复写

### Step 5 未落实建议跟进（写库后必做，不等用户问）

Step 4 写库完成即执行——评估校正只记录"落实情况"是不够的，未落实的建议若无出口，等于评估白做。

1. **范围**：本批次全部 `落实情况` ≠「已采纳」的条目，含三类：
   - **未采纳**
   - **部分采纳**——与未采纳同等对待，且隐蔽性更高（意味着仍有渠道/环节留着原问题）
   - **留空未填**——按未采纳处理并标注"（管理员未填，请确认）"，**不静默当已采纳**（与 levels 留空同规则）
2. **两维分流**（按活动当前 status × 建议性质；悟空起草，用户拍板，**未拍板不写海马体**）：

   | 活动 status | 建议性质 | 处置 |
   |---|---|---|
   | 进行中 / 待上线 | **对客风险类**（对客文案、宣传口径、权益披露与门槛、授权合规、客服联系方式、应急预案、第三方权责） | 起草一条海马体待办：活动名＋建议原文＋落实情况＋**到期日**（取 end_date；无则取上线日） |
   | 进行中 / 待上线 | **内部文档类**（评估表内部表述、佐证材料补交、机构名称填写等不对客的） | 只留档，不挂待办 |
   | 已结束 / 已下线 / 已取消 | 对客风险类且已实际上线过 | 不挂待办；提示用户是否沉淀 `knowledge/cases/` 或 `声誉风险事件库/`（知识轨，发现即入库） |
   | 已结束 / 已下线 / 已取消 | 内部文档类 | 只留档 |

3. **留档**：**仅对有未落实条目的卡**，在其「评估建议采纳情况」节末尾追加一行 `未落实跟进：共N条（对客风险类M条）——<处置结论>`；条目本身已带落实情况，不重复罗列；全部已采纳的卡不加此行（不留噪声）
4. **写库变更清单**同步列出分流结果，供 Web 侧呈报与留痕
5. 「部分采纳」且属对客风险类的，跟进清单须注明"**缺口范围未知，建议回问管理员/处室具体哪部分未落实**"——校正表「说明」列常留空，不能凭"部分"二字推断残留风险面

### Step 6 写库后订正（发现校正表填错时）

写库完成后才发现校正表填错（落实情况、等级填反或笔误）：

1. **卡片是事实源**，直接改，并在该条目后括注 `（校正表原填"X"系笔误，YYYY-MM-DD 管理员订正）`
2. **批次原始件不改**——`网页直填-解析结果.json` / 已填 xlsx 是填报留痕，改了就失去对账基准
3. `写库变更清单-YYYY-MM-DD.md` 追加 `⚠️ 订正` 条：原值、订正值、订正日期、以何为准
4. 已写 `knowledge/log.md` 的，在原记录内补注，**不新开一条**
5. 若订正的是**风险等级**：除上述外还须回改卡片 `risk_level` 与 INDEX 等级列，并核对是否连带影响盯盘窗口与报备要求（三级及以上须提前 3 个工作日报总行办公室）

## 二、事后采集

### Step 1 圈批次

两条路，都只提醒/生成，不静默写库：

1. **会话启动自动扫描**：读 `knowledge/活动方案库/INDEX.md` 预筛——仅对状态=已结束、或时间窗终点已过的行打开对应卡片核对（时间窗为"待填/~/非日期"的行跳过）。满足 `source: internal` + `end_date` 为合法 ISO 日期且严格小于今日 + `feedback_status` 为空 → 提醒 `👂 谛听提醒 | N个活动已结束待采集：[活动名列表] | 建议生成采集表`（end_date 为推断值时标注"终止日为推断，请先与处室确认活动确已结束"）。只提醒，用户点头才生成
2. **触发词「事后采集」**：用户手动触发，列出待采集活动 +「表已发」超10个自然日未回收的批次。此入口下支持：
   - **强制重入批**：把「表已发/已回填」的活动重新采集（表弄丢、活动延期后二次采集），重置状态并在批次清单注明轮次
   - **长期活动阶段性采集**：end_date 为空/`~`/年底的长期活动手动纳入某批做阶段性采集，不改卡片 status，回填后 `feedback_status: 阶段采集-YYYY-MM-DD`

### Step 2 生成

1. 组装批次JSON（无需读报告，活动条目不含 `suggestions` 字段）：批次号按 `work/事后反馈采集/` 下当月现状取下一号；活动按 `dept` 分组成 `files` 数组，每处室一份 `采集表-YYYY-MM-批次N-<处室名>.xlsx`
2. 批次JSON 存到 `work/事后反馈采集/YYYY-MM-批次N/批次清单.json`
3. 运行：`python scripts/diting_excel.py generate <批次目录>/批次清单.json <批次目录>`
4. 逐张卡片 `feedback_status` 标 `表已发-YYYY-MM-DD`
5. 提示用户转发各处室；用户发出后说一声，悟空在批次清单.json 对应 file 条目补 `sent_date`

### Step 3 解析回填（用户说「解析」时）

1. 定位批次：用户给已填文件路径；未给路径 → 列出在途批次让用户选
2. 运行：`python scripts/diting_excel.py parse <已填xlsx> <批次目录>/批次清单.json <批次目录>/解析结果-<处室>.json`
3. 检查 warnings（缺 sheet/脏值/字段未找到），有问题先报用户
4. 读取 `effects` 字段转译成卡片「事后回填」段草稿（处室口语→内部格式，按卡片模板两类小节结构）：
   - **「预判的坑是否应验」由悟空比对「评估建议采纳情况」节（若已有）+ 本次实际投诉舆情数据自行推断**；若该活动尚未做过评估校正（该节不存在），注明"评估校正尚未进行，仅凭本次实际数据判断"
   - 「真实教训」由悟空提炼
5. 草稿呈用户确认后才写库：卡片事后段 + `feedback_status`（填全→`已回填-日期`；有缺口→用户定 `部分回填-日期` 还是保持 `表已发` 等补充）+ status 改「已结束」（阶段性采集不改）+ 更新 INDEX 状态列

### Step 4 收尾

1. 有应验的坑/新教训 → 建议用户同步沉淀 `knowledge/cases/`（悟空起草）
2. 调青云技能（anzhi-qingyun）同步一次活动库（失败仅报告，不阻塞）
3. `knowledge/log.md` 记一条——**插在文件顶部**（前言 `---` 之后、当前最新条目之前），该文件按日期降序，勿追加到文件末尾

## 状态字段速查

**review_feedback_status**（评估校正，按前缀匹配）：
| 值 | 含义 |
|----|------|
| （空） | 待校正，进扫描 |
| `校正表已发-YYYY-MM-DD` | 已生成待回收 |
| `已校正-YYYY-MM-DD` | 完成出队 |
| `免校正-原因简述` | 无需/无法校正，人工关闭 |

**feedback_status**（事后采集，按前缀匹配）：
| 值 | 含义 |
|----|------|
| （空） | 未采集，进扫描 |
| `表已发-YYYY-MM-DD` | 已生成待回收 |
| `已回填-YYYY-MM-DD` | 完成出队 |
| `部分回填-YYYY-MM-DD` | 已答部分回填，缺口待补 |
| `阶段采集-YYYY-MM-DD` | 长期活动阶段性采集，活动未结束 |
| `免采-原因简述` | 取消/不适用，人工关闭 |
