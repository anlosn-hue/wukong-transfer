# 千里眼 — 同业及本行周度舆情监测报告

**声明：** 我正在使用千里眼技能，生成周度舆情监测报告。

---

## 核心原则

1. **实事求是**：只收录监测周期内实际发生的事件，没有就写"本周无"
2. **不硬凑**：不拿历史旧闻、过期案例凑数
3. **内部参阅定位**：报告供总行内部决策参考，不对外发布，不发处室
4. **与活动评审分离**：只写舆情监测和应对建议，不写活动规则整改（另出评审报告）
5. **周期红线**：搜索结果发生日期不在监测周期内的，一律不纳入报告

## Phase 0：初始化

**Step 0.1 — 确认监测周期**

询问用户本次监测起止日期。若用户未指定，默认本周一至今（今日）。

**Step 0.2 — 读取配置**

读取配置文件，提取"同业固定名单"字段（逗号分隔银行名列表）。

若文件不存在或名单为空，停止并提示：
> 千里眼配置文件缺失或同业名单为空，请先填写：`knowledge/tools/assessment-manual/private/千里眼配置.md`

**Step 0.3 — 读取活动方案库，构建在途活动清单**

读取 `knowledge/活动方案库/INDEX.md`：

1. 提取"活动名"和"舆情关键词"两列内容，作为 Phase 2 判断同业动态是否与本行活动场景相似（机会性发现）的参考基准
2. 筛选状态为「进行中」或「待上线」的活动，构建**在途活动清单**（字段：活动名、类型、时间窗、风险等级、舆情关键词、状态），供 Phase 3.5 定向搜索和报告第四部分使用

若文件不存在，跳过此步，Phase 2 机会性发现环节改为凭常识判断，Phase 3.5 与报告第四部分省略（不阻断流程）。

## Phase 1：银行业整体+监管 WebSearch

对监测周期内逐日执行 WebSearch：
```
银行 舆情 YYYY年MM月DD日
```

另外执行：
```
银行 投诉 热点 YYYY年MM月
银行业 监管政策 YYYY年MM月
```

**筛选**：
- 仅保留发生日期落在监测周期内的结果
- 仅保留与银行业整体强相关、**不点名具体银行**的行业动态或监管政策类内容（点名具体银行的动态归入 Phase 2 或 Phase 3）

---

## Phase 2：同业专项动态 WebSearch

对 Phase 0.2 读取的同业固定名单，逐家银行执行两组查询：
```
{银行名} 活动 OR 试点 OR 创新
{银行名} 投诉 OR 舆情
```

**筛选与体量控制**：
- 每家银行最多收录 1 条最具参考价值、发生日期落在监测周期内的动态
- 无实际发现的银行不列，不强求凑满全部家数
- 搜索过程中若发现固定名单外的银行有与 Phase 0.3 读取的活动库场景（活动名/舆情关键词）高度相似的动态，额外收录，标注【机会发现】前缀；数量不设上限，但需在【与本行的关联】字段写明相似的具体活动场景

**可信度约束（严格执行）**：
- 每条动态必须包含来自本次搜索结果的原始来源和日期
- 禁止凭记忆补充案例，所有内容来自本次搜索结果

## Phase 3：本行专项 WebSearch

执行：
```
兴业银行 YYYY年MM月 新闻 事件
兴业银行 投诉 舆情 YYYY年MM月
```

**筛选**：仅保留发生日期落在监测周期内、与兴业银行直接相关的舆情条目（含负面、中性公告类）。

## Phase 3.5：在途活动同业类似风险 WebSearch

针对 Phase 0.3 构建的在途活动清单，定向搜索**其他银行在同类活动场景下近期出的问题**，为本行在途活动提供前车之鉴。

**Step 3.5.1 — 场景分组**

把在途活动按玩法/场景去重分组（避免逐活动搜索导致查询爆炸），典型分组如：
- 抽奖/立减金类（好运签、转盘抽奖等）
- 积点任务/权益兑换类
- MGM 裂变/推荐转赠类
- 理财营销推送类
- 系统维护/服务暂停类

**Step 3.5.2 — 逐组搜索**

每组执行 1-2 条查询，查询词 = 「银行」+ 场景词 + 症状/投诉词，症状词优先取该组活动舆情关键词中的症状词。示例：
```
银行 抽奖 立减金 未到账 投诉
银行 推荐 活动 积点 套路 投诉
银行 APP 系统维护 打不开 投诉
```

**筛选**：
- 仅保留发生日期落在监测周期内（或周期临近、仍在发酵）的同业案例
- 本行条目不收（归 Phase 3）；每组最多收录 2 条最具警示价值的
- 与 Phase 2 已收录条目重复时只保留一处，在第四部分标注"详见第三部分同业N"

**可信度约束**：同 Phase 2，每条必须有本次搜索结果的原始来源和日期，禁止凭记忆补充。

## Phase 4：报告生成（.md 底稿）

按以下结构生成 Markdown 报告：

### 封面

```
银行舆情监测报告
YYYY年M月D日—YYYY年M月D日
由总行数字运营部声誉风险管理智能体生成，供内部参阅
监测范围：银行业整体舆情 + 同业专项动态 + 在途活动同业风险比对 + 兴业银行专项舆情
数据来源：公开网络搜索、黑猫投诉相关搜索、新闻媒体
```

### 第一部分：本周舆情概览

表格：

| 类别 | 数量 | 说明 |
|------|------|------|
| 银行业本周实际舆情热点 | N条 | 简述 |
| 同业专项动态 | N条 | 简述 |
| 在途活动同业类似风险 | N条 | 简述 |
| 兴业银行本周专项舆情 | N条 | 简述 |
| 监管政策动态 | N条 | 简述 |

**【本周核心发现】**：3-5条，最后一条为"前瞻研判"（时点敏感性判断）

### 第二部分：银行业本周舆情热点

【说明】以下为本周期内实际发生的行业动态，部分与本行关联度较低。

每条格式：
```
## 热点N：事件标题

【发生日期】YYYY年MM月DD日
【舆情摘要】200字以内，时间+主体+事件+结果
【舆情走势】中性/正面/负面 + 简要判断
【对银行的启示】1-3条，具体可操作
【来源】媒体名称（YYYY-MM-DD）
【关联度】★★★★★
```

没有就写：本周在公开渠道未监测到与本行高度相关的银行业舆情热点。

### 第三部分：同业专项动态

【说明】以下为同业固定名单（工商银行/农业银行/中国银行/建设银行/交通银行/邮储银行/招商银行/中信银行/民生银行）本周期内的专项动态，聚焦活动/试点/创新及相关舆情投诉，供本行活动设计与风险防控参考。

每条格式：
```
## 同业N：[银行名] 事件标题 [【机会发现】可选前缀]

【发生日期】YYYY年MM月DD日
【动态摘要】200字以内
【与本行的关联】该动态与本行哪类活动场景相似/有何警示意义
【参考价值】★★★★★
【来源】媒体名称（YYYY-MM-DD）
```

没有就写：本周期内同业固定名单未监测到值得参考的专项动态。

### 第四部分：在途活动与同业类似风险比对

【说明】以下为本行当前在途（进行中/待上线）活动清单，及同类活动场景下同业近期出现的风险案例，供各活动运营处室对照防范。

**在途活动清单**（来自活动方案库，截至报告生成日）：

| 活动名 | 类型 | 时间窗 | 状态 | 风险等级 | 舆情关键词 |
|--------|------|--------|------|---------|-----------|
| ... | ... | ... | 进行中/待上线 | X级 | ... |

**同业类似风险**（Phase 3.5 搜索结果，按场景分组）：

每条格式：
```
## 比对N：[场景组] [银行名] 事件标题

【发生日期】YYYY年MM月DD日
【案例摘要】200字以内
【涉及本行在途活动】列出同场景的本行活动名
【警示要点】1-2条，对照本行活动的具体防范动作
【来源】媒体名称（YYYY-MM-DD）
```

没有就写：本周期内未监测到与本行在途活动场景相似的同业风险案例。（在途活动清单仍照列，不省略。）

### 第五部分：兴业银行本周专项舆情

【说明】开头注明"本周未监测到兴业银行负面舆情"或"本周监测到N条"

格式同第二部分，聚焦兴业银行。

没有就写：经监测，本周（X月X日-X月X日）黑猫投诉平台、微博、小红书、知乎等渠道未出现兴业银行相关集中投诉或负面讨论。

### 第六部分：监管政策动态

```
## 动态N：政策名称

【发布日期】YYYY年MM月DD日
【政策要点】核心内容简述
【对银行的影响】具体影响分析
【来源】发布机构/媒体（YYYY-MM-DD）
```

没有就写：本周期内未监测到新发布的银行业相关监管政策。

### 第七部分：本周舆情监测总结与建议

**一、总体舆情基调**

一句话定性（如"本周银行业舆情环境呈'平静中性'态势"）+ 关键判断

**二、下周监测重点**

列出3-5个下周需重点关注的舆情风险点

**三、对兴业银行近期活动的具体建议**

| 建议项 | 具体内容 | 优先级 |
|--------|---------|--------|
| ... | ... | P0/P1/P2 |

【说明】此处只写舆情监测和应对建议，不写活动规则整改（另出评审报告）

**四、监测数据来源说明**

列出本周实际使用的数据来源

## Phase 4.5：过体例规范（.md 底稿完成后、转 docx 前）

逐条过 `knowledge/tools/报告体例规范.md`。**周报是七个部分的叙述型文本，B/C/E 三类最容易踩**：

- **B1/B4** 报告不解释自身做法。删「本报告分析…」「本期启用的检索策略如下」「结论是」「判定逻辑是」「需要说明的是」等铺垫语——检索方法、Phase 划分、WebSearch 策略一律不进正文（「四、监测数据来源说明」只列实际用到的来源，不讲怎么检索的）
- **B2** 同一说明只出现一次。同一事件在「银行业热点」与「同业专项」都命中时，详写一处、另一处引指，不重复铺陈
- **C1** 概率表述不夸大：不写「必将」「势必」「大概率演变为」，写「可能」「存在…的压力」
- **C3** 建议归建议，不冒充制度：第七部分的建议不得自造阈值、复审机制或考核要求
- **C5** 判断句必须能指回来源。「总体舆情基调」的一句话定性须有本周实际检索到的事件支撑，指不回就不写
- **D4** 破折号超 3 处逐处审查；**D6** 禁模糊归因——「业内人士认为」「有观察指出」一律换成具体媒体/机构与时间，或删
- **D2** 「**标题：** 说明」式内联标题列表改连贯段落或表格
- **E 类**高频词黑名单：此外、至关重要、赋能、格局、凸显、彰显、助力、打造、抓手、韧性、不仅…而且、标志着、见证了等。**舆情周报尤其容易写成宣传腔，这一类要重点扫**
- **A1** 内部术语不进交付件：Phase 编号、情报源代号、技能名

**明确不适用**：
- **A2 行名**——本技能是同业对比，「兴业银行」及各同业行名是正文必需内容，**一律原样保留，不得改写为「总行」或做任何替换**（用户 2026-07-25 定）
- **A5 诉点** —— 本技能不涉及投诉菜单命名
- **D1 emoji** —— 一律保留

## Phase 5：docx 生成（轻量版）

用 document-skills:docx 技能，将 Phase 4 生成的 .md 内容转为结构化 docx：
- 主标题 + 封面四行信息（居中或顶部说明文字）
- 各部分用标题层级（Heading 1 / Heading 2）
- 表格用 docx 表格（本周舆情概览表、建议表）
- **不套本单位公文模板**，不加页码、不加公文式落款格式——本报告是内部参阅，非发处室正式公文

**排版硬约束（2026-07-10 新增，防弱模型排版走样，逐条执行不可省）：**
- 同一层级文字字号必须统一：正文一律同号，Heading 按层级各自统一，**严禁同段落内混用字号**（2026-07-10 Web 版运行出现字大字小混排，本条即为此固化）
- 日期区间一律带分隔符写作 `YYYY-MM-DD~YYYY-MM-DD`（或"至"），**严禁两个日期直接粘连**（如 2026-07-112026-07-19）——本条同时适用于 .md 底稿，生成前对全文做一次 `\d{4}-\d{2}-\d{2}\d{4}` 模式自检，命中即修
- 生成后自检（不可跳过）：重新打开 docx 抽查各节字号一致性与日期分隔符，不符即修 gen 脚本重新生成，直到通过再交付

**降级容错**：docx 生成工具不可用时，仅保留 .md 底稿，提示用户手动转 docx，不阻断流程。

## Phase 6：文件导出

**目录与文件命名规则：**

```
目录：./work/舆情监测/YYYYMMDD-YYYYMMDD-千里眼周报/
文件：银行舆情监测报告_YYYY年M月D日—YYYY年M月D日.md
文件：银行舆情监测报告_YYYY年M月D日—YYYY年M月D日.docx
```

- `YYYYMMDD-YYYYMMDD` = 监测周期起止日期（目录名，纯数字）
- `YYYY年M月D日—YYYY年M月D日` = 监测周期起止日期（文件名，中文格式，沿用 Kimi 原型已验证命名）

**执行步骤：**
1. 创建目录（若不存在）
2. 写入 .md 底稿
3. 生成 .docx（Phase 5）
4. 告知用户两个文件的完整路径
