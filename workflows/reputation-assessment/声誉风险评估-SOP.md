# 声誉风险评估 — 操作规程（SOP）

> 适用材料：活动方案 / 宣传内容 / 系统上线文档 / 对外声明
> 所处审批环节：处室声誉风险自评后，流转至**部门舆情管理员**（本环节）

---

## 第一步：接收并识别材料

- 确认 scene 类型：营销文案 / 活动规则 / APP内容 / 客服话术 / 推送策略 / 系统上线 / 对外声明
- 确认申请处室、申请时间、材料版本号

## 第二步：逐场景排查隐患

- 打开 knowledge/tools/声誉风险事件库/ 找到对应场景文件（01-数字营销活动 / 02-系统建设 / 03-客户服务 / 04-内部管理与合作方）
- 逐项核查，标记存在的隐患点，记录隐患描述和建议修改方向

## 第三步：套用六维评估法

- 六维评估法已由 `knowledge/tools/六维规则库/` 下的 Markdown 规则文件取代（`声誉风险六维评估法.xlsx` 为历史版本，规则库为当前权威依据）
- 从六个维度逐项判断，综合得出审核结论及修改建议，特别是对于声誉风险评估表和应急（回撤）预案，要具体到段落的修改意见

评估时可参考以下知识库资源（均在 `knowledge/` 目录下）：

| 知识库 | 路径 | 用途 |
|--------|------|------|
| 声誉风险事件库 | `tools/声誉风险事件库/` | 按场景分类的历史风险事件参考，含常见漏洞模式 |
| 历史案例库 | `cases/` | 已积累的内部案例与行业参照，含舆情监测积累案例 |
| 国家法律法规库 | `tools/管理机制/国家法律法规/` | 六维评估的上位法规依据 |

## 第四步：确定风险等级

依照 knowledge/tools/assessment-manual/声誉风险分级模型.md（孰高原则）：

| 等级 | 后续处理 |
|------|---------|
| 一级（极高） | 立即上报，暂停材料发布，走紧急流程 |
| 二级（高） | 上报综合处主要负责人，等待指示后处理 |
| 三级（中） | 提出修改建议，提交综合处主要负责人 → 部门主要负责人 → 发办公室 |
| 四级（低） | 记录在案，输出评估意见，可建议通过 |

## 第五步：填写评估意见反馈表

- 这里也就是要填写完成第三步的成果，要求有理有据
- 按"YYYYMMDD-项目名-申请处室-评估意见"命名保存，不放回 templates/

## 第六步：写 daily/ 记录

在 knowledge/daily/YYYY-MM-DD.md 追加：

```
## 评审记录
- [材料名称]：[简要判断] → [结论] | 判断理由：[一句话]
```

## 第七步：判断是否升格 cases/

若本次评审有值得复用的判断逻辑或典型隐患，升格为 cases/ 文件（格式规范见 memory/关于工作.md）。
升格后检查同 scene 的 cases/ 数量，若已有 2 条以上，提示安之考虑提炼 internal-comms/ 文档。
