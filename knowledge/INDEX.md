## 各目录文件格式规范

> 2026-07-24 从 `memory/关于工作.md` 搬来。**格式规范跟着数据走，不放 memory/**——写在记忆里离数据太远，改文件的人看不到，必然漂移（原 cases/ 规范要求 frontmatter，实际两个新文件一个都没写）。

| 目录 | 规范位置 |
|------|---------|
| `cases/` | [cases/INDEX.md](cases/INDEX.md)「文件格式规范」节（详细版：命名/首部字段/正文结构/双向指针/登记要求） |
| `活动方案库/` | `templates/活动卡片模板.md`（frontmatter 字段与枚举以模板为准） |
| `daily/` | 见下 |
| `internal-comms/` | 见下（该目录是 gitignored junction，规范不能放其内部，故登记于此） |

**`daily/`（工作日志原材料）**

- 命名：`YYYY-MM-DD.md`，有实质工作时才创建，不强制每天
- 结构：`## 评审记录`（`[材料/活动名]：[简要判断] → [结论] | 判断理由：[一句话]`）／`## 新发现`（隐患类型/新规则/新判断）／`## 待处理`（需升格 cases/ 的条目）
- 粒度：结论 + 一句话理由；完整推理写进升格后的 `cases/` 文件

**`internal-comms/`（经验提炼文档）**

- 命名：`场景名-主题.md`，例如 `营销文案-常见隐患模式.md`
- frontmatter：`scene`（对应场景）／`updated`（最近更新日期）／`source_cases`（来源案例文件名列表）
- 结构：`## 背景`（这类场景为何容易出问题）／`## 常见隐患模式`（`[模式]：[触发条件] → [典型表现] → [处置方向]`）／`## 评审要点`／`## 典型案例参考`
- 提炼触发：同一 scene 的 `cases/` 累计 ≥3 条且此处无对应 `场景名-*.md`
