## 文件格式规范

> 2026-07-24 从 `memory/关于工作.md` 搬来并按实际重写。**格式规范跟着数据走**——写在 `memory/` 里没人看得到，规范说要写 frontmatter、实际两个新 case 一个都没写，就是这么漂移的。
> 上级定位说明（cases 与事件库的分工）见 `memory/关于知识.md`「事件库 vs cases 定位区别」。

**文件命名**：`YYYYMMDD-事件关键词.md`。日期取**事件曝光/评审日**（非事发日；事发日写进正文首部）。

**无 frontmatter**，首部用列表字段：

```
- **日期**：YYYY-MM-DD（曝光/评审日）；事发另注
- **场景**：与本 INDEX 的 scene 列一致（内部·xxx / 行业参照·xxx）
- **涉及**：涉事主体、客群
- **严重度**：高/中/低，或风险等级（一~四级）
- **对应事件库要点**：`声誉风险事件库/0X-xxx.md` #N（双向指针，见下）
```

**正文结构**（按需取用，非全部必填）：

| 节 | 何时写 | 内容 |
|---|---|---|
| 检索关键词 | 案例可能被多种说法搜到时 | 按 行为/客群/渠道/业务/症状/定性 分组铺同义词 |
| 事实 | **必写** | 时间+主体+经过+结果，附来源与日期 |
| 案例解读 | 值得深挖的重案 | 为什么会发生、后果为何不可逆、根因在哪 |
| 教训 / 排查要点 | **必写** | 下次遇到类似情况的具体动作 |
| 监管依据 | 涉法条时 | **先查 `tools/管理机制/国家法律法规/` 本地全文**，本地无收录再外检索 |
| 关联 | **必写** | 回指事件库要点编号、相邻要点辨析、周报/log 出处 |

**双向指针（写任一边都要补另一边）**：事件库条目的「关联案例」→ 指向本目录文件；case 的「对应事件库要点」→ 指回事件库条目编号。

**写完必做**：在上方表格登记一行（文件/scene/关键词/时间范围/条数）。**cases 是按 INDEX 选择性加载的，不登记＝对火眼金睛、照妖镜等于不存在，且不会有任何报错。**

**scene 计数提示**：同一 scene 累计 ≥3 条且 `internal-comms/` 下无对应 `场景名-*.md` 时，提示安之考虑提炼经验文档。
