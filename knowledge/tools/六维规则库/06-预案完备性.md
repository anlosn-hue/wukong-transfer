# ⑥ 预案完备性 · 规则库

> 来源：声誉风险事前评估表（第三节：处置预案；第四节：媒体备答口径）。
> 本维度与事件库联动强：调取同场景常见预案遗漏点。

---

## 1. 预案类型与适用场景

| 预案类型 | 必须提供的场景 | 核心要素 |
|---------|-------------|---------|
| **应急预案** | 营销活动类、宣传内容类、权益发放类 | 触发条件 + 回撤步骤 + 客户告知 + 善后处理 |
| **回撤预案** | 系统上线类、平台功能上线类 | 触发条件 + 响应时限 + 处置流程 + 舆情口径 |
| **两者均须** | 大型营销活动（系统+内容同步上线） | 分别完整提供 |
| **简版预案** | 四级低风险事项 | 至少包含：触发条件 + 联系人 + 基本处置步骤 |

---

## 2. 应急预案 · 要素清单

适用场景：营销活动、宣传推文、优惠券/权益发放、大规模短信/企微推送。

### 必须包含的要素

| 要素 | 说明 | 不合格示例 |
|------|------|----------|
| **触发条件** | 何种情况启动回撤，有明确可量化指标 | "出现问题时"（不合格，无法操作） |
| **回撤步骤** | 具体操作流程，含渠道下线顺序 | "立即停止活动"（不合格，无操作步骤） |
| **客户告知方式** | 已参与/已收到推送的客户如何告知 | 未提及客户告知（不合格） |
| **告知时效** | 回撤后多久内完成客户通知 | 无时效约定（不合格） |
| **已发放权益处理** | 已发券/已扣积分如何处理 | 未提及（不合格，易引发投诉） |
| **舆情应对口径** | 如有客户投诉/媒体询问，回撤期间的统一口径 | 未提及（建议提供，非强制） |

### 触发条件参考标准

| 场景 | 参考触发阈值 |
|------|------------|
| 活动规则错误（展示与实际不符） | 发现即触发 |
| 大规模客户反馈异常（投诉数量） | 建议约定：如1小时内投诉超过X条即触发 |
| 系统故障导致权益无法正常兑付 | 系统故障持续X分钟即触发 |
| 监管/舆情突发情况 | 监管要求或媒体大规模负面报道即触发 |

---

## 3. 回撤预案 · 要素清单

适用场景：系统上线、新功能发布、数据对接、平台扩容。

### 必须包含的要素

| 要素 | 说明 | 不合格示例 |
|------|------|----------|
| **触发条件** | 何种系统状态启动应急（故障类型/影响范围/时长） | "系统出现问题时"（不合格） |
| **响应时限** | 初步响应时间要求（通常1小时内完成初步处置） | 无时效约定（不合格） |
| **内部上报链路** | 通知哪些人，通知顺序 | 仅写"通知相关人员"（不合格） |
| **处置流程** | 故障定位→临时应急→问题修复各阶段操作步骤 | 仅写"排查修复"（不合格） |
| **客户告知** | 是否需要通知受影响客户，如何通知 | 未提及（不合格） |
| **舆情应对口径** | 客户/媒体询问时的统一口径 | "按实际情况回答"（不合格） |

## 4. 媒体备答口径 · 质量标准

来源：声誉风险事前评估表第四节。

**质量要求：**
- 至少提供1条Q&A格式口径（问题+对应回答）
- 口径语气：专业、中性、不回避，不过度承诺
- 覆盖最可能被问到的问题

**常见必须覆盖的问题：**
- "你们的（活动/系统）出现了什么问题？"→ 事实陈述口径
- "受影响的客户如何处理？"→ 善后口径
- "为什么会发生这种情况？"→ 原因解释口径（谨慎，避免不当承诺）

**不合格口径示例：**
- 仅写"按实际情况回答媒体" → 无法操作
- 口径中含有"我们保证..."等不当承诺 → 存在法律风险

**时态规范（2026-07-08 安之提出，通用注意事项）：**

应急预案/回撤预案里的媒体备答口径，措辞时态须站在"问题已经发生"的时间点写，而不是沿用面向客户的提前公告（预告性/未来时）表述。

- 提前发布的对客公告（如"XX服务将于X月X日暂停"）使用未来时是对的，因为公告本身就是提前发布的预警。
- 但备答口径服务的场景是**故障/问题已经发生之后**媒体或客户来询——此时若直接照搬提前公告的"届时""将于……暂停"式措辞作为回答，会造成时态错位：对方问的是"正在发生/已发生的事"，回答听起来却像"未来的计划"，削弱口径的真实感和说服力。
- 判断方法：假设按预案中标注的执行/触发日期已经到达，媒体此刻来问，回答该用"已经/正在……"的既成事实语态，而不是"届时/将……"的未来语态。
- 常见错误来源：备答口径table直接复制了对客公告原文，未按"公告发布 vs 事件发生后询问"两个不同时间点重新改写。
- 检查方法：核对备答口径中每一条的"适用场景"是否标注为"事件发生中/超时/已回撤"等既成状态；若是，回答栏出现"将/于X月X日/届时"等未来时措辞即标注 ⚠️。

## 5. 常见预案遗漏点

| 遗漏点 | 常见场景 | 提示方式 |
|-------|---------|---------|
| 已发权益/已扣积分的处理 | 营销活动回撤 | ⚠️ 客户已获权益的处理方式未明确 |
| 不同渠道的关闭顺序 | 多渠道营销回撤 | ⚠️ 未说明APP/企微/短信各渠道关闭顺序 |
| 媒体口径 | 中高风险事项 | ⚠️ 建议补充备答口径 |
| 夜间/节假日应急联系人 | 系统上线 | ⚠️ 未提供7×24小时应急联系机制 |
| 数据备份方案 | 系统数据迁移 | ⚠️ 未说明数据回滚机制 |

## 6. 网评引导预案（生成型输出，2026-07-08 新增）

本节与前五节性质不同：前五节检查**处室的预案是否完备**，本节是悟空**直接替处室备弹药**——预判负面帖并生成网评员可直接使用的引导评论。

**生成条件（涉客判定）：** 判断维度是"是否对外发布、客户能否直接感知"——对外发布的内容或客户能直接感知变化的事项（营销活动、对客公告/宣传内容、触客话术、系统停服/功能变更通知等）每次生成；仅涉及内部运营、客户无法感知的事项（处室制度发文、内部流程调整、组织体系变更等）跳过并注明"内部事项，网评预案不适用"。

**三段固定结构：**

1. **负面帖预判**：基于本次事项的具体风险点，写 1–2 个最可能出现的负面帖画像（平台+口吻+抱怨点，如"抽了十次都没中，又是内定吧"）
2. **5 条风格各异的引导评论**——每条必须基于本次活动真实权益点/规则撰写，禁止模板套话：

| 风格 | 定位 |
|------|------|
| 理性科普型 | 摆流程摆规则，澄清误解 |
| 亲历者现身说法型 | 第一人称真实体验对冲负面 |
| 网感玩梗型 | 轻松化解，适合抖音/小红书评论区调性 |
| 正面直夸型 | 直给好评，垫热评区 |
| 降温引流型 | 引导找官方客服，把情绪导入私域处理 |

3. **使用注意（固定附带）**：不同账号错峰发布；不逐字照抄，发布前按各自语气改写；按平台调性微调——整齐划一刷屏会被截图打成"水军控评"，引发二次舆情，此为红线提醒。
