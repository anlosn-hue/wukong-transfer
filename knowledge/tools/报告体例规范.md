# 行内报告体例与去 AI 化规则

> **适用**：悟空对外/对上交付的一切正式报告类文档——金箍棒月度投诉分析报告、紧箍咒服务合规体检报告、千里眼周度舆情监测报告、火眼金睛/照妖镜评估意见书。
> **不适用**：`memory/`、`docs/`、`work/` 下的内部工作底稿与过程记录。
>
> **依据**：2026-06 月度投诉分析报告经处室同事修订模式归纳（61 处插入 / 101 处删除 / 63 段 / 9 条批注），补以 `Humanizer-zh-main` 中适用于公文的条目。
> **建立**：2026-07-25（安之裁定 A4/A5/D1 三项）

---

## ⚠️ 明确不适用的条目

`Humanizer-zh-main` 第 23、24 条「个性与灵魂」——有观点而非中立报道、使用第一人称"我"、允许一些混乱、幽默与锋芒、对感受要具体。

这些是创作类文本的规则，套到行内报告上会直接写坏。反证：本次修订中「登录失败的成因**是三件具体的事**」被改回「包括三个方面」。

**公文路径永不执行该节**——这也是 `anzhi-style-decoder`（王语嫣）SKILL.md 把公文排除在 Humanizer 之外的原因。本规范补的是公文自己那一套，不是把非公文规则搬过来。

## A 类 · 术语与口径

**硬规则，违反 = 事实错误。默认全改。**

> ⚠️ **A2、A5 的适用范围须严格限定**（安之 2026-07-25 定）：
> - **A2 只管「部门名称」这一个字段**——数据范围表的涉及部门、责任机构、主办单位等处，把「兴业银行XX部」写成「总行XX部」。**不是"凡见『兴业银行』就换成『总行』"**：正文里作为行名出现的「兴业银行」保持原样，不得批量替换。
> - **A2 只适用于客户投诉分析报告（金箍棒）**。千里眼同业对比、火眼金睛／照妖镜评估意见书里行名是必需的，一律保留，不做任何改写。
> - **A5 只管投诉／督办的菜单命名**。紧箍咒「质检发现问题点」、火眼金睛「六维结论＋问题点」是正常中文用词，与投诉诉点无关，不改。
>
> 其余各条（A1 内部术语、A3、A4、A6、A7、A8 系列、B/C/D/E 全部）对所有交付件通用。

| 编号 | 规则 | 反例 → 正例 |
|---|---|---|
| A1 | **内部方法论术语不得出现在交付件**：L1/L2/L3 分级、模型代号、Phase/Step、"分批深挖"层级说明、技能名 | "已全部完成 L2 抽样深挖" → "已全部完成抽样深挖" |
| A2 | **部门名称字段**写「总行XX部」，不写「兴业银行XX部」；不得列入本期数据未出现的部门。**仅限部门名称位置，不涉及正文中作为行名的「兴业银行」** | "兴业银行零售信贷部" → "总行零售信贷部"<br>"兴业银行零售金融部/消费者权益保护办公室/养老金融部" → "总行零售金融部"<br>（实现：`run_analysis.data_scope()` 过 `底库/部门映射.yaml`，只作用于机构字段） |
| A3 | **跨表对比时写「投诉单」「督办单」**——同一句里同时给出两张表的数量时，须用「单」把两类工单分开。**单表陈述不要求**（"共受理客户投诉3797条"加「单」反而累赘，安之 2026-07-25 定选项2） | "近3个月投诉仅60笔，当月督办却高达142笔" → "近3个月**投诉单**仅60笔，当月**督办单**却高达142笔"<br>"当月合计585条（投诉侧329条、督办侧256条）" → "（**投诉单**329条、**督办单**256条）" |
| A4 | **用字：诉求**（不是"述求"） | 2026-07-25 安之裁定；同事修订中的"述求"不采纳 |
| A5 | **「诉点」＝投诉点的简称，只用于投诉侧**；督办侧对应位置写「各类问题」。任何情况下不写自造的「问题点」 | 投诉侧："各类诉点环比明细"<br>督办侧："各类问题环比明细" |
| A6 | **限定词不得越界**："全行""全量""首次"须与数据口径严格一致 | "全行督办超时办结率" → "督办超时办结率"（本报告口径非全行） |
| A7 | **定义须用行内口径**，不得按字面推断 | 督办 = 客户来电沟通中**未命中**投诉关键词、已受理登记尚未形成正式投诉单的事前预警工单<br>投诉 = **已命中**投诉关键词并形成正式投诉单 |
| A8 | **诉点/问题名称一律写全称「业务细分二级菜单-业务细分三级菜单」**，原样取自源数据，不得简写、改写、只写一级或只写三级 | "短信未达与延迟问题" → "短信问题-短信未达、延迟问题"<br>"财富管理部兜底类目" → "其他财富业务问题-无法归入上述内容的涉及财富管理部相关投诉"<br>（源数据「业务细分一级菜单」实为部门名，不参与拼接） |
| A8a | **跨表命名不一致时以归一映射表为准，并在「报告说明」章披露映射关系**。A8 的"原样取自源数据"仅适用于单表内；两张源表对同一业务概念命名不同时，"各自原样取"会让跨表匹配静默失效 | 实例：督办表「借记卡增值**服务积点权益**问题」= 投诉表「借记卡增值**权益服务**问题」。因未归一，2026-06 漏报 1 个红色预警（详见 `docs/superpowers/plans/2026-07-25-月度投诉分析报告V3.md` 查证 4）。**任何按拼接字符串跨表精确匹配的模型，都必须配套归一映射 + 回归测试** |
| A8b | **跨月/跨期统计一律以归一化后的 `底库/*.csv` 为准，不得回到原始 xlsx 手工数列** | 原始区可能有多个文件（如按月分卷），只看其中一个会漏月；且不同年份 sheet 的列顺序会漂移（2025 年 sheet 比 2026 年多一列「意见来源」，菜单列整体后移）。2026-07-25 核red 警笔数时两处同时踩中，把 238 误算成 132 |

| A9 | **预警级别一律写全称**：红色预警／橙色预警／黄色预警。不写「红警」「橙警」「黄警」，也不写「红/橙预警」这类合写（安之 2026-07-25 定） | "13个红警" → "13个红色预警"<br>"仅含红/橙预警" → "仅含红色、橙色预警"<br>（`report_lint` A9 规则报红；注意脚注 KEY `〔fn:红警〕` 是内部键名、不进正文，不受此条约束） |

> A5 补充：无行内既有说法时**先问再用**，不得自行命名并在全文推广。自造术语一旦铺满全文，返工成本极高。

## B 类 · 元话语

**默认删除。这是行内报告最主要的 AI 味来源。**

| 编号 | 规则 | 说明 |
|---|---|---|
| B1 | **报告不解释自己**：章节层级说明、内部方法论层级、统计过程说明，一律不进正文 | 需要留痕的移入附件或工作底稿。本次被整节删除的「（四）分析层级说明」+ L1/L2/L3 表格即属此类 |
| B1a | **例外（安之 2026-07-25 定）：数据范围与口径、预警级别认定规则、分析模型清单可留在正文「报告说明」章**，但须与相邻小节**并表精简**，不得各占一节反复铺陈 | 分析模型清单与「（二）预警级别认定规则」并表。读者需要知道指标怎么来的；不需要知道悟空内部分几层跑 |
| B2 | **同一说明只出现一次** | 超时口径变更说明本次在结论摘要、督办章、策略建议各写一遍，三处全删 |
| B3 | **不写给作者自己看的操作提示** | "（首次打开请右键此处选择「更新域」以生成目录页码）" |
| B4 | **删除铺垫式引导语**，直接给结论 | "结论是……" / "判定逻辑是：……" / "需要说明的是……" / "预警的含义是……" / "本期启用的模型如下" / "本报告分析……两张表口径不同" |
| B5 | **不预先替读者辩解** | "不代表客户已经向监管部门反映"（删）；"与历史报告对比时须注意口径差异"（删） |

| D14 | **文末注释表不用列表自动编号** | `<ol>` 的 1. 2. 会与条目自带的 `[1][2]` 撞成「1. [1] …」。保留 `[n]` 与正文上标一致，关掉 `list-style`（安之 2026-07-25 定） |

## E 类 · AI 高频词黑名单

守门用。2026-06 报告实测命中极低（命中次数：闭环 4、"此外" 2，其余为 0），优先级最低，但保留检查。

此外、与……保持一致、至关重要、深入探讨、强调（动词）、持久的、增强、培养、赋能、格局（抽象）、凸显、彰显、助力、打造、抓手、韧性、生态（抽象）、宝贵的、充满活力的、值得注意的是、不仅……而且、这不仅仅是……而是、标志着、见证了、是……的体现/证明、关键转折点、为……奠定基础
